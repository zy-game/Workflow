# 规范清单（提炼自 AGENTS.md / docs / skills）

按领域分组的可执行规则。原仓库每条规则基本都配一个机械化门禁，借鉴时建议同样为每条规则指定"用什么脚本/CI 卡住它"。

## 代码规范

- 注册即效应：插件的所有贡献走 `ctx.effect()` / `ctx.on()`，`register()` 返回 disposer。
- 判别标签 switch：封闭联合以 `assertNever` 收尾；可扩展联合走文档化的 default 分支。
- Waterfall 监听器必须调 `next()` 委托；不调即短路整条链。
- 空的 `catch` 必须命名它吞掉了什么、为什么没有其他路径能到达；`try` 保持单语句。
- 不注释代码已显见的事实；注释只写代码表达不了的非显式契约与理由。
- 并行值保持对称；无解释的不对称通常是漏掉一次抽取的信号。
- 跨边界 opaque id 用品牌类型 `Branded<B>`，不用裸 `string`。
- 包边界显式化：默认值解析是显式 `resolve(request): Spec` 步骤，不是 `run()` 里隐藏的 `?? default`。
- 插件无可调硬编码：随部署变化的取值进 `Config`（可从配置文件改）；协议常量/安全不变量除外。
- 配置失败要响亮：加载期能判定的就在加载期报错；绝不静默跳过缺失引用。
- 优先维护良好的依赖而非手写：当依赖真能删掉自有代码和测试时（权衡净删除量，包装层搬运复杂度不算赢）。
- 文件以恰好一个换行结尾，pre-commit 用 `git diff --cached --check` 卡住。

## 类型与构建

- `strict: true` + `noImplicitAny`；每个存留的 `any` 解释为何无法收窄。
- 同进程有类型保证的边界信任类型系统，不加运行时校验/回退/敌意测试；在解析/配置、队列、模型 JSON、落盘、worker、进程、线缆边界校验。
- 源码面与构建产物面分离：静态门禁解析到 `src`，消费 `lib/` 的门禁显式声明。
- 每包一个聚合 compiler face（`api/remotes` 例外）；仓库级程序 seed 一个 face 配置而非根 solution。

## 测试规范

- 覆盖率门禁是 `test:coverage`（按文件 100%）而非 `test`；CI 拥有穷举覆盖与平台矩阵。
- 为意图中的回归选最窄检查：行为→专项测试；模型/用户可见输出→快照；文档→doc-sync；发布路径→build+hygiene+冒烟；供应商行为→e2e。
- 绝不为提交或推送重复跑已通过的检查；绝不用 `--passWithNoTests`、降覆盖率或收窄 `--coverage.include` 来隐藏未覆盖文件。
- 测试描述行为而非正确性：行为过时则连测试一起改，PR 里解释原因。
- 断言要在意图回归上失败，验证外部状态/日志/事件/disposal，而不是复述实现。
- 夹具必须在 macOS/Linux 重放；修夹具而不是修 normalizer。
- 真实入口路径：测试要走过发布物的 Loader/bin/worker/子进程，而非手工挂载的插件。

## 文档与注释规范

- **完整命题规则**：编辑前枚举段落全部命题（主体/行为、条件/时序、情态 must/may/never、负向保证与例外、所有权/副作用/失败/后果）；每个事实子句幸存才算合格删减，字数下降本身不是改进。
- 一处事实一个家：本质契约可在使用点局部保留，架构/理由/算法链接到 owning 文档。
- 术语自查：`contract`/`boundary`/`shape`/`seam` 使用前先问有没有更精确的词（`response fields`、`JSON validation`、`ESM exports`）。
- 公共 JSDoc 文档化：调用方可见的返回区分、抛出/拒绝、副作用、所有权、时序、取消、持久化。
- 文档随代码同 PR 更新：配置、默认值、错误、线缆字段、事件、公共行为变了，包 README 与 JSDoc 同 diff 更新。
- 代码跟随文档结构再改散文：先定位层级、设定允许细节度（本页主题全细节，直接子级摘要，更深层链接到 owning 后代）、区分教程 vs 参考、拆分混合形态。
- 重命名/移动文档是原子操作：移出旧家 + 移入新家 + 修完所有入链，同一次变更。

## 注释卫生（CoT 泄漏，AI 协作仓库通用）

对每段可疑注释问一个问题：**HEAD 上的读者，拿不到任何会话记录/PR 线程/未提交草稿，能否解析每个引用、验证每个断言？** 不能则改写幸存事实为仓库视角再删其余；不携带事实子句的直接删除。八类泄漏：

1. 死设计会话引用（`(decision 7)`、`audit C2`、`plan §4`、阶段代号 T4/W3）。
2. 栈/PR 视角（"本栈后续 PR"、"本 PR 新增"、"上一个提交"）。
3. 变更叙述与版本戳（"used to"、"no longer"、"v1"、"这次裁剪"）。
4. 评审编排（"评审中被拒"、"reviewer 确认"、草稿序号 v5）。
5. 对评审者喊话的自证（"这个 cast 是安全的，因为…"）。
6. 复述与推导记录（"先 X 后 Y"控制流叙述、测试走查）。
7. 对冲与计划残渣（"暂时应该够用"→ 升级为 TODO 或写明真实边界）。
8. 母语滑入（中文碎片留在英文散文里，或反之）。

保留项：issue 引用、已合并 PR 引用（限 ADR/postmortem）、压制理由（lint-disable reason）、反事实回归钉（"没有 X 就会 Y"）、实测边界（"measured: 512 nests ≈ 0.15s"）、运行期新旧状态（连接排水）、外部标准章节（RFC §）。

## Git 与 PR 规范

- 重写历史只用 `--force-with-lease=<branch>:<observed-oid>`；裸 `--force` 永远禁止。
- 独立改动拆开 PR；修 introducing PR 再传播，不在下游打补丁。
- 栈式 PR 用 GitHub 官方 stack 对象与 `gh stack merge`，不手工逐个 merge + retarget。
- 重写推送后重新获取 head，重审未解决评审线程/批准/可合并性/检查——旧 commit hash 不是当前证据。
- 标签：一个 PR 一个 `kind/*`，实质影响的都打 `area/*`。
- TODO 语义分级：`FIXME`/`TODO`/`XXX` 按紧急度。

## Agent 协作规范（对 AI 编码代理的约束）

- 报告只报实际跑过的命令；未跑不说跑过。
- 沙箱导致的工具失败（凭证/网络/IPC/嵌套 sandbox 被阻）先用最窄的宿主升级原样重试，再诊断"认证或项目失败"；要求有沙箱证据，绝不绕过真实测试失败或被测产品沙箱。
- 未决检查如实报 pending；不因为命令成功就声称栈已就绪。
- 收到评审意见逐条技术核实或反驳，不做表演性认同。
