# 设计哲学（提炼自 DeepSeek Harness）

## 1. 一切皆插件

Cordis 框架之下，产品没有特权核心：模型适配器、工具注册表、会话日志、agent 循环本身全部是插件，因此**任何部分都可以从配置替换**。

- **注册即效应**：一切贡献走 `ctx.effect()` / `ctx.on()`，注册返回 disposer，插件卸载时全部可逆回滚。没有"挂上去就摘不下来"的补丁点。
- **能力缝隙（capability seam）三角色**：Service Definition（接口声明）/ Service Provider（实现）/ Consumer（消费）。三者齐备才算一条完整 seam；只有当角色各自演化时才拆分。这是"什么该是一个包/一个接口"的判定单位。
- **插件优于改循环**：新行为落在文档化的扩展点上；要改 `agent-loop` 本身时必须先更新架构文档——把"动核心"的成本显式抬高。

## 2. 事件域选择

事件是扩展点，选对域是大多数改动的第一个决策：

- **Session events**：追加进日志的持久事实。事实必须在重载后幸存时用它。
- **Agent events**（`agent/*`）：携带活体 Agent 的在途观测——收件箱、步骤、状态、请求校验。
- **Capability events**（`fs/*`、`tools/*`）：把策略和适配器挂上 seam 而不侵入循环。

**Model-visible ⟺ logged**：凡是进入模型请求的内容，必须能从会话日志重建；新增一个模型可见输入就必须新增一个会话事件。可重建性是硬不变量，不是风格偏好。

## 3. 边界纪律

- **显式 > 隐式**：默认值解析是 owning 实现里一个显式的 `resolve(request): Spec` 步骤，绝不是 `run()` 里隐藏的 `?? default`。
- **校验放在真边界**：同进程有类型保证的调用信任 TypeScript，不加运行时校验；在解析器/配置、队列、模型与工具 JSON、落盘文件、worker、进程、线缆这些边界才做校验。
- **Opaque id 用品牌类型**（`Branded<B>`），跨边界 id 永远不是裸 `string`。
- **源码面与构建产物面永不混合**：静态门禁通过 tsconfig paths 解析到 `src`；消费 `lib/` 的门禁显式声明该依赖。
- **插件里不写死可调参数**：随部署变化的取值是可从配置修改的 `Config` 字段；`DEFAULT_*` 常量或测试钩子不算可配置性。协议常量、外部规范与安全不变量保持固定。
- **配置错误要响亮**：自包含时在加载期报错，否则在最早可解析点报错；绝不静默跳过缺失引用。

## 4. 工程文化

- **发布前：地基优先于爆炸半径**。没有外部消费者时优先做对的地基而非兼容垫片：自由重命名、重打包并同步更新所有引用；后端直接拒绝旧落盘格式。
- **证据匹配改动面**：行为改动跑最窄的专项测试；模型/用户可见输出跑快照；文档跑 doc 门禁；真实供应商行为跑 e2e。**绝不默认全量套件，也绝不为了提交或推送重复跑一次已通过的检查**——穷举覆盖和平台矩阵归 CI。
- **非平凡变更必须同 PR 附 Agent Note**（ADR），且 `Alternatives considered` 强制：没有记录"击败了什么"的决策 invites re-litigation（引来反复重议）。
- **Postmortem 门槛三条件**：subtle（机制不明显）、systemic（逃逸原因是测试/工具/规范的系统性缺口）、costly to rediscover（真实调试成本）。三个都满足才写。
- **测试描述行为，而非正确性**：行为变了，测试跟着变，并在 PR 里解释为什么。
- **快照走真实可运行示例**：模型/产品可见行为的每个非平凡变更，通过真实组装应用的 transcript 加密钥无关快照；mock 专用夹具不替代组装后的 transcript。
- **GUI 变更的证据链**：改了产品用户可见的 GUI 行为，PR 必须带从该 PR 真实服务+真实模型流录制的演示 GIF，并标注被演示的确切 commit、启动方式与是否有真实模型轮次。绝不用夹具查询、mock 传输或合成事件替代。

## 5. 防御性模式（每条都来自真实事故）

1. **独立结果独立上报**：一个结果可以同时是几件事（进程超时 AND exit 0）。每个独立事实（`timedOut`/`signal`/`exitCode`）单独呈现，绝不把一个标志的报告嵌在另一个的分支里。
2. **公共契约两侧都遵守**：实现内部允许多种失败表示，但穿过公共 API 前必须归一化，消费者不该猜测异常来自 provider、包装层还是自己的组装。
3. **异步状态不是同步状态**：`agent.followup()` 没有单消息完成语义；后台任务完成与轮次边界竞争。真正拥有一次运行的调用方必须显式定义自己的区间；同时必须处理"等待的转换永不发生"分支，否则挂死。
4. **Dispose 要到达静默，而非仅发出请求**：清理必须异步并 await 子进程退出（kill → await done），且在杀进程**之前**关闭监听器/通知注册表，让迟到的完成保持静默。
5. **回调异常困在分发器内**：用户监听器抛错不能拒绝所在 Promise，也不能饿死后续监听器；分发循环 try/catch + 记日志。
6. **不给不可信输出环境变量或可预测路径**：派生命令用清洗过的 env（剔除 `*KEY*/*SECRET*/*TOKEN*/*PASSWORD*`）；临时/溢出文件用 0700 私有目录 + 随机名 + 属主独占打开（`'wx'`, `0o600`）。
7. **链接形路径用 unlink**：可能是符号链接/junction 的路径先 `lstatSync().isSymbolicLink()` 再 `unlinkSync`；递归删除只留给已知的真实目录。

## 6. 值得借鉴的元设计

- **规则不是愿望，是门禁**：字数预算、注释覆盖、ADR 格式、归档密封全部有 `verify-*` 脚本在 CI 强制。写规范时同步想"用什么脚本卡住它"。
- **知识分四态管理**（proposed / implemented / rejected / archived）：rejected 只在"仍能防止一个诱人错误"时保留；archived 冻结密封、永不编辑、不是当前权威。
- **一处事实一个家**（one home per fact）：本质契约可在使用点局部重复，但解释与理由只在一个 owning 文档，其余地方链接过去。
