# DSH RC.8 更新与 Windows TUI EXE

## 默认交付决策

- DSH 目标固定为公开最新预发布 `@deepseek-ai/dsh@0.1.0-rc.8`，整个 DSH 包族使用精确版本，禁止混装 RC.7/RC.8，也不使用仍指向 RC.7 的 `latest` 标签。
- `dsh-neotui` 保留当前受控 fork `0.3.0-dsh.1`。其上游最新版仍是 `0.3.0`，直接替换会丢失本地登录、Core gateway 和安全缓存改动。
- 生产升级采用“隔离演练 -> Core gateway 上线 -> 中央 DSH -> Linux Worker -> Windows Worker”的顺序。RC.8 SQLite 格式不兼容，回滚必须同时恢复 RC.7 程序和升级前数据快照。
- 先交付未签名的 Windows x64 单文件 EXE 和便携 ZIP。当前机器没有受信任代码签名证书或 `signtool`；发布清单会明确 `signed: false`，不会用自签名冒充正式签名。

## 1. 先补齐受认证的 Core DSH gateway

当前 Nginx 将 `/dsh/` 直接转发到中央 DSH，绕过 Workflow Core 对 `wfc-*` token 的验证。正式 EXE 发布前先修复这一安全与功能缺口。

- 在 `workflow-core/packages/core/src/gateway/` 增加 HTTP/WebSocket 反向代理：
  - 仅接受经 `AuthRepository.getClientAccessToken()` 验证的 `wfc-*` bearer token。
  - HTTP 代理 `/dsh/api/*`，转发时删除 `/dsh` 前缀、`Authorization`、公共 `Host` 和 hop-by-hop headers。
  - WebSocket 仅允许 `/dsh/api/events.mux` 与 `/dsh/api/events.host`，升级前完成同样的 token 验证。
  - DSH 仍只监听 `127.0.0.1:3081`，客户端永不直连。
- 将 gateway 连接到 `createCoreServer()` 和 public server 的 `upgrade` 处理，与现有 `/worker` 通道按路径分流。
- 修改 `ops/nginx/workflow-admin.conf`，让 `/dsh/` 转发到 Core `127.0.0.1:18710`，保留 WebSocket upgrade headers。
- 从旧 `wf-api` 移植并加强集成测试：有效、缺失、伪造、过期、登出/吊销 token；两条 WebSocket；prefix/query 保留；上游不得收到凭据；拒绝请求不得触达假 DSH。
- `dsh-client --check` 不再把任意 HEAD 状态视为成功：它应确认 TLS、Core health，以及未认证 `/dsh/api/host.describe` 被 gateway 以 `401` 拒绝。真实登录后 `host.describe` 和两个 WebSocket 才构成完整可用性证据。

## 2. DSH RC.8 隔离升级与数据迁移

- 在 `dsh-workflow/package.json` 和 lockfile 中把所有直接与传递 DSH 包统一锁到 `0.1.0-rc.8`，保留 Node 24 和受控 registry/integrity 证据。
- 基于 RC.8 实际包更新 schema/domain descriptors、验证常量和迁移逻辑；不沿用 RC.7 的 `application_id`、`user_version` 或表结构假设。
- 构建独立 RC.8 runtime bundle，不覆盖 `C:\ProgramData\WorkflowCore\runtime` 或服务器当前 release。
- 对中央 DSH、Windows Worker 和 Linux Worker 的数据目录做只读快照，然后在副本上执行迁移：
  - SQLite integrity/foreign-key/schema 检查。
  - session headers、events、attachments、storage domains 和内容哈希对照。
  - 源副本保持不变；迁移过程可重复运行或明确拒绝二次迁移。
- 增加真实 RC.8 DSH 契约测试，覆盖 Worker/Core 当前依赖的私有协议：启动参数、`host.describe`、session create/prompt/history/cancel、history pagination、events.mux、approval respond、model/settings/credentials、完成事件及重启恢复。
- 更新 Windows installer 的精确版本门禁、运行手册和 cutover manifest；修正旧 `8711` 与当前内部端口 `18711` 的文档漂移。

## 3. TUI Windows 与协议修复

在受控 fork 中做最小必要调整，不重写界面：

- 把 CLI 参数解析拆成可测试模块，支持 `--base`、`--workspace`、`--resume-session`、`--cache-root`、`--check`、`--version`、`--help`，并拒绝未知参数/缺失值。
- 将 `Start-DshTui.ps1` 的 HTTPS `/dsh`、Linux workspace、cache path 与检查逻辑移入 JS 入口；PowerShell 脚本仅保留为源码开发兼容入口。
- 修复 Windows 行为：
  - `/restart` 用 `process.execPath` 重启 SEA，不调用 `sh`。
  - 默认编辑器使用 `notepad.exe`。
  - 本地文件打开使用 Windows shell，不调用 `xdg-open`。
  - 不在 Windows 上误调用 `wl-copy/wl-paste`。
- 明确本地/远程文件边界：远程 Linux workspace 通过 DSH RPC 浏览；本地 attachment picker 从 Windows 用户目录开始；不把 Linux cwd 交给本地 `readdirSync`。
- 统一可写目录：配置/主题放 `%APPDATA%\DshTui`，cache/log 放 `%LOCALAPPDATA%\DshTui`，token 始终只在内存。
- 把版本在 bundle 时编译进代码，移除 SEA 中无效的 `import.meta.url -> package.json` 运行时读取。
- 更新 README 中“本地文件不暴露”的错误描述，改为“仅用户明确选择的本地附件会上传”。

## 4. 构建单文件 Windows x64 EXE

在 `dsh-client` 增加可复现的 Node 24 SEA 构建：

- 固定 Node `24.15.0`、`esbuild@0.28.2`、`postject@1.0.0-alpha.6`、`rcedit@5.0.2`、`yazl@3.3.1` 与 `ws@8.21.0`，全部写入 lockfile，不在发布时使用浮动 `npx`。
- `esbuild` 将 ESM 图和 `ws` bundle 成单个 CommonJS `sea-main.cjs`，不保留非内置运行时依赖。
- 校验官方 Node ZIP 和 `node.exe` SHA-256；使用 Node SEA 生成 blob，关闭 snapshot/code cache，再注入复制的 `node.exe`。
- 添加 Windows console manifest：`asInvoker`、UTF-8、long-path、Windows 10/11 compatibility 和版本资源。
- 生成以下产物：

```text
dsh-client/dist/DshTui-1.0.0-win-x64/
  DshTui.exe
  README.txt
  THIRD-PARTY-NOTICES.txt
  release-manifest.json
dsh-client/dist/DshTui-1.0.0-win-x64.zip
dsh-client/dist/DshTui-1.0.0-win-x64.zip.sha256
```

- `release-manifest.json` 记录 DSH/NeoTUI/Node/构建工具版本、源与目标哈希、架构、gateway contract revision、签名状态；不得包含 endpoint token、密码、会话或项目数据。
- 无证书时产物完整交付但标记未签名；若以后提供受信任证书，只在 SEA 注入完成后执行 Authenticode 和 RFC3161 timestamp。

## 5. 验证与生产切换

- 单元/契约：Core gateway、auth repository、真实 DSH RC.8、Worker、TUI parser/Windows helpers、remote transport。
- EXE 静态/无依赖：`--help`、`--version`、错误参数、`--check`；PE x64 console/manifest/version；bundle 无外部 npm 依赖；ZIP 解压后在无 Node 路径环境执行；secret scan 和 SHA-256 校验。
- TUI 交互：Windows Terminal 中登录遮罩、中文、resize、paste、mouse、Ctrl+C 终端恢复、401/403 重新登录、WebSocket reconnect、SQLite cache、restart、export、本地附件选择。
- 网关端到端：Core 登录获取 `wfc-*` token；有效 token 完成 unary RPC 和两条 WebSocket；伪造/吊销 token 无法触达 DSH。
- 生产切换前保存：Core release 指针、中央/Worker RC.7 runtime、DSH 数据目录、Windows scheduled-task 配置及哈希清单。
- 按阶段升级并在每阶段检查 Core health、Worker 注册/模型 revision、真实无害任务、TUI 登录与恢复；任一步失败立即停止后续阶段。
- 回滚时恢复 RC.7 runtime 与对应升级前数据快照，禁止 RC.7 打开 RC.8 数据。最终提供 EXE/ZIP 路径、哈希、版本矩阵、生产状态和剩余签名限制。
