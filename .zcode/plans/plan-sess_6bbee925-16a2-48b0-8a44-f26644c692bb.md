## 背景

「账号运维」（docs/18-账号运维.md，设计稿）可以推进，但**发布一律不做**：B站/微博/知乎账号还没给，且注册需要手机短信+实名，我无法自主完成（docs/18 §9.2 本身也规定登录由人在机器的 Chrome 里完成）。你要求先把过于简陋的后台网页端做了，再推进账号运维。

本轮按两条走：**① 重做网页端（零构建重构）**；**② 按文档落「最小内容层」后端 + 账号运维控制台**，让面板操作真实数据（content_item / variant / action 账本、闸门预算、人审流），不含任何平台连接器与发布执行。账号到位后即可从 S1 微博只读继续。

现状：apps/web 是零构建单文件 vanilla（app.js 2497 行、10 面板、约 45 个 REST 端点 + SSE），由 host-gateway 静态托管（7410 端口，Bearer/cookie/?token= 三种鉴权）；apps/mobile/www/app/ 有一份近乎相同的副本（app.js 字节一致）。仓库测试为 `node --test`，前端契约靠 apps/web/test/ui-contract.test.ts（正则对文件断言）。

## 二、网页端重构（apps/web，零构建）

保持原生 ES module、零新依赖，把单文件拆成模块：

```
apps/web/public/
  index.html        壳：侧栏导航（桌面）/底部标签（≤640px）+ hash 路由 + 聊天主区
  app.js            入口：路由 + 启动（薄）
  lib/api.js        fetch 封装 + ENDPOINTS 表 + 鉴权（?token=/cookie/密码登录，行为照旧）
  lib/sse.js        EventSource + 退避重连（事件名不变）
  lib/ui.js         表格/表单/徽标/时间格式化等共享组件
  panels/*.js       chat/tasks/schedules/memories/autonomy/conversations/incidents/review/audit/settings/content
  style.css         统一 CSS 变量（补上缺失的 --muted/--ink 定义）、卡片/表格组件类
```

- hash 路由替代现有「互斥 toggle」（面板可深链 `#/tasks`）。

## 三、最小内容层后端（新包 packages/qm-content）

- 账本：`qm_content_item` / `qm_content_variant` / `qm_content_action` 三个 collection（provider-store-sqlite 的 `collection()` + `ensureIndex`，JSON 行）。
- 状态机（§6，代码层 A 类）：item `idea→drafting→drafted→reviewing→approved→published→archived / rejected(reason)`；variant `pending→rendering→ready→scheduled→publishing→live / failed`。非法迁移抛错；`publishing/live` 无执行器，自然不可达。
- 闸门与预算（§7，B 类配置）：插件 config 里配 `budgets {publish:2, reply:20, mention:10}`、静默 23:00–08:00、冷却间隔；`status()` 返回今日用量余量 + 各平台接入状态（当前一律「未接入」）。
- REST（qm-approval 的 `gateway.route` 模式）：`GET/POST /api/v1/content`、`GET/PATCH /api/v1/content/:id`、`POST .../review|approve|reject|archive`、`POST/GET .../variants`、`GET /api/v1/content/status`。变更发布 SSE `content-updated`。
- MCP 工具（host-mcp）：`content_draft` / `content_variants` / `content_status`，失败返回 `{ok:false, reason, retryable}`；权限键与审计按 qm-approval/qm-task 既有写法。
- 挂载：qingmei.yml / qingmei.prod.yml 增加插件条目。
- 测试：状态机迁移、预算/静默闸门、路由契约（仿 qm-autonomy 用 in-memory store + 假服务）、ui-contract 扩展。
