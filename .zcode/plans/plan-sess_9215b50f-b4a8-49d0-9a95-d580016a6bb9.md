## 目标修正

不使用 C# Source Generator，也不生成 workflow C# 文件。Workflow 是类似 ShaderGraph 的可组合图资产/运行实例：原子能力节点保持独立可调用；多个节点可组合成复合 Workflow 节点；复合 Workflow 还能嵌套到更大的图中。

新增的关键要求是：目标项目没有现成 Workflow 时，其他 CLI 可以声明所需能力和组合关系，由 UnityBridge 动态发现节点并在本地创建、校验、执行新的 Workflow。默认同时支持“临时执行”和“保存为可复用版本”：CLI 可要求一次性运行，也可提交一个命名版本供后续发现和复用。

## 阶段三：统一节点契约与动态发现

定义稳定的、与 Core HTTP DTO 解耦的节点协议：

```csharp
public interface IUnityBridgeNode
{
    NodeDescriptor Descriptor { get; }
    ValueTask<NodeResult> ExecuteAsync(
        NodeExecutionContext context,
        CancellationToken cancellationToken = default);
}
```

`NodeDescriptor` 包含：

- 稳定 `nodeTypeId`、版本和 display name。
- 输入/输出端口、类型、必填项、默认值、校验规则。
- Runtime/Editor 执行环境。
- capabilities、超时、取消、进度、幂等和交互声明。
- 敏感字段标记、可组合性和副作用分类。

现有 Skill/Action Handler 通过 adapter 暴露为原子节点；单节点调用、图内调用和子图调用复用同一执行器。

增加能力目录接口（本地 Bridge API + Core/CLI 查询适配）：

```text
ListNodeDescriptors(filter)
GetNodeDescriptor(nodeTypeId, version)
ListWorkflows(filter)
GetWorkflowDescriptor(workflowId, version)
ValidateComposition(composition)
PlanComposition(requirements, constraints)
ComposeWorkflow(spec, saveMode)
RunNode(invocation)
RunWorkflow(invocation)
```

CLI 不依赖目标项目预先存在某个 Workflow。它先查询 Bridge 的能力目录，按稳定 nodeTypeId/version、输入输出类型、capability、执行环境和副作用约束筛选可用节点，再发送组合规格。Bridge 返回缺失能力、类型不匹配、循环或 Editor/Runtime 冲突等结构化诊断，而不是静默替换节点。

## 阶段四：ShaderGraph 风格复合 Workflow

### 图资产与边界

- `WorkflowGraph : BaseGraph` 保存可编辑图资产，拥有稳定 workflow ID、版本、公开输入/输出接口。
- `WorkflowInputNode` 和 `WorkflowOutputNode` 定义图边界。
- `SubgraphNode` 引用 WorkflowGraph，并映射其公开端口；Workflow 可直接运行，也可嵌套。
- 节点引用使用稳定 nodeTypeId/version 和 workflow asset GUID/version；运行时固定版本，编辑图不会改变已开始运行的语义。
- 图验证器检查端口类型、必填项、重复/缺失 ID、循环、不可达节点、缺失引用、版本不兼容、能力冲突和 Editor-only 节点进入 Runtime 图。
- 禁止递归子图引用；输出端口变更需要版本迁移或兼容检查。

### 动态组合

CLI 发送的是逻辑组合描述，而不是本地路径或代码：

```json
{
  "workflow_id": "optional-logical-name",
  "save_mode": "temporary|versioned",
  "inputs": [{"name": "source", "type": "..."}],
  "outputs": [{"name": "result", "type": "..."}],
  "nodes": [
    {"id": "a", "node_type": "...", "version": 1, "parameters": {}},
    {"id": "z", "node_type": "...", "version": 1, "parameters": {}}
  ],
  "edges": [{"from": "a.out", "to": "z.in"}]
}
```

- `temporary` 图只存在于本次调用的受控运行上下文；`versioned` 图写入 UnityBridge 管理的资产目录并登记 descriptor，供后续 CLI/项目发现和复用。
- 组合前做 deterministic normalization 和 validation；相同规范组合应得到相同 composition fingerprint，避免重复版本和歧义。
- 动态图不允许把凭据、token、环境值、本地绝对路径写入图资产、Core payload、日志、索引或诊断。
- 保存的 Workflow 只包含逻辑参数和公开接口；项目特定资源通过受控本地引用/运行时解析，不上传路径。

## 阶段五：执行生命周期与 Bridge transport

实现：

```csharp
IWorkflowBridgeTransport
IBridgeStateStore
IBridgeCredentialProvider
IBridgeTaskExecutor
IBridgeExecutionContext
IWorkflowNodeCatalog
IWorkflowComposer
IWorkflowExecutor
```

Transport 负责 register、pull、heartbeat、events、interactions、result、release、稳定 request/event ID、重试和歧义恢复。Bridge journal 持久化 claim、lease、outbox、未确认事件和终态结果，支持断网、domain reload、Unity 重启和取消；token 只从受控来源读取。

执行适配器把 Core task 转换为单节点 invocation 或 Workflow invocation，并映射 `done/report/failed/blocked`。所有 Unity API 回到 Editor 主线程；长任务使用可恢复状态机和 progress/timeout/cancel/interaction 语义。

Core 只接收普通任务：

- 单节点调用：task payload 指向 nodeTypeId/version 和逻辑输入。
- Workflow 调用：task payload 指向 workflowId/version 或本次组合规格的受控引用。
- Bridge pull 不作为 CLI 的直接发布接口。
- Core 继续负责任务、claim、lease、重试、依赖、交互和终态；UnityBridge 不建立第二个远程调度中心。

## 关键决策

- 不使用 Source Generator，不生成 workflow C# 文件。
- Workflow 是版本化图资产和运行时解释执行的复合节点。
- 原子节点只有一份实现；可单独调用，也可作为图节点或子图节点复用。
- CLI 通过能力目录发现节点，并可动态提交临时或版本化组合规格；目标项目不需要预先创建 Workflow。
- NodeGraphProcessor 只负责 Editor 图形化和资产编辑，不能承担 Transport、持久化或 Core 任务权威。
- Core 是唯一任务权威；UnityBridge 不复制远程调度器。
- Runtime 节点与 Editor-only 节点分层。
- 所有凭据、token、环境值、本地绝对路径留在受控本地边界，不能进入 Core payload、日志、索引、图资产、诊断或知识记录。
