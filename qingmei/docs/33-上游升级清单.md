# 33 · 上游升级清单（Cordis / DSH）

青梅把「内核」和「大脑」都外包了：`cordis@4.0.0-rc.12` 是应用容器，内嵌 DSH 通过 ACP 提供推理与工具。
两者都在快速演进，升级不能靠 `pnpm update` 了事。

## 1. 锁在哪

| 依赖 | 锁定位置 | 当前 |
| --- | --- | --- |
| cordis | 根 `package.json`（精确版本） | 4.0.0-rc.12 |
| DSH | 服务器 `/usr/local/bin/dsh`，配置里 `command` | 见 `dsh --version` |
| Node | 根 `package.json` engines / 服务器 `/opt/node24` | >= 24 |

升级前记录现状：

```bash
node -e "console.log(require('./node_modules/cordis/package.json').version)"
ssh ubuntu@139.155.78.241 '/usr/local/bin/dsh --version; /opt/node24/bin/node -v'
```

## 2. 升级 Cordis

1. 改根 `package.json` 的精确版本 → `pnpm install`（不要 `^`）；
2. 跑 `pnpm gate`：架构检查（0 reflect / 0 跨包 collection）+ 全部类型检查 + 412 条测试；
3. 跑 `node scripts/smoke.mjs`：起服务 → 发消息 → 落库 → 重启后还在；
4. 本地 `node scripts/deploy.mjs --skip-tests` 部署，确认 healthz 三渠道在线；
5. 保留回滚：supervisor 会留下上一版 release，`shell.mjs activate <旧 id>` 可切回。

重点回归项（这些地方直接用 Cordis 语义）：

- 插件生命周期：`ctx.plugin()` 必须 `await`；`ctx.effect` 的清理顺序；
- `inject` 依赖就绪：缺 provider 时插件应 `PENDING` 而不是崩；
- 事件：`events.emit` 不等监听器，落库顺序依赖 `events.parallel`。

## 3. 升级 DSH（ACP）

1. 先在**本机**换 DSH，用 `node scripts/harness-worker.mjs` 或 `provider-dsh-acp` 的测试跑通；
2. 重点确认 ACP 协议面没变：`initialize` / `session/new` / `session/prompt` / `session/cancel` /
   `session/load` / `session/request_permission` / `fs.read_text_file` / `terminal.*`；
3. 确认 usage 是否开始回报——如果回报，`tokenBudget` 才能从摆设变成真限制（见 docs/13 §12.1）；
4. 生产升级：换 `/usr/local/bin/dsh` → `systemctl restart qingmei` → healthz + 一次真实对话；
5. 回滚：保留旧二进制（`dsh.prev`），重启即回退。

## 4. 不许做的事

- 不要用 `pnpm update` 一次升一批依赖；
- 不要把 Cordis 改成 `^` 范围；
- 不要在没跑 gate + smoke 的情况下直接换生产 DSH；
- 不要在没有 release 历史的情况下升级（supervisor 至少要有一个健康旧版可切回）。
