# 12 · 规则分层：代码、策略、提示词

> 「有些规则是不是不用写成代码？」——是，但只有一类可以。
> 分不清这三类，就会把安全边界写成一句提示词，然后指望模型自觉。

## 1. 两种极端都不对

| 极端 | 形态 | 后果 |
| --- | --- | --- |
| 全代码 | 每句回复、每个判断都 if/else | 僵化，写不完，人格像机器人 |
| 全提示词 | 把"不要泄露隐私""别改核心代码"写进 system prompt | 一次注入、一次模型升级就可能破防，且无法举证 |

正确形态是分层：**能不能做用代码，怎么做用提示词；可变的用配置。**

## 2. 三类规则

| 类 | 名称 | 载体 | 谁改 | 生效 |
| --- | --- | --- | --- | --- |
| **A** | 硬边界 | 代码 | 只有发版 | 重启 / 换版 |
| **B** | 策略 | 数据（YAML/DB） | 你在后台改 | 立即 |
| **C** | 表达与判断 | 提示词 / 人格 / 技能包 | 改文件或热更 | 下一条消息 |

### A · 硬边界（必须是代码）

- 敏感数据能不能出网（`secret` 不进云模型）
- 群聊能不能读私聊记忆（audience 过滤）
- 自进化能改哪些文件（L3 禁改清单）
- 不可逆操作必须确认（转账、删库、发消息给外部）
- 审计不可丢、不可改
- 预算与速率上限
- 补丁必须过测试、必须可回滚

**判据：错了会不会造成不可逆后果，且必须能事后举证。** 会 → A。

### B · 策略（必须是数据）

- 群标签 → 可见范围 / 工具白名单 / 回复长度（见 [11](11-群画像与回复策略.md)）
- 打扰预算、静默时段
- 渠道优先级、降级顺序
- 模型路由（哪类任务走哪个模型）
- 记忆召回预算

**判据：你会不会想每周改一次？** 会 → B。写在代码里就等于逼你重新发版。

### C · 表达与判断（交给模型）

- 语气、称呼、幽默度、什么时候简短
- 怎么解释一个复杂决定
- 该追问还是该给结论
- 任务怎么拆、代码怎么写、报告怎么组织
- 「这句话在群里怎么说才得体」

**判据：是否存在多种都正确的答法？** 是 → C。写死只会僵化。

## 3. 一句话分工

> **A 与 B 决定"能不能说、能不能做"，C 决定"怎么说、怎么做"。**

所以"群里不透露进度"这件事，不是 C（让模型自觉），而是 B（策略）+ A（上下文裁剪）。
模型在吹水群里**根本拿不到**进度数据，它再怎么被诱导也说不出没有的东西。

## 4. 反模式

| 反模式 | 为什么错 |
| --- | --- |
| 在 prompt 里写"绝对不要泄露隐私" | 可被注入绕过；模型升级后行为漂移；出事无法举证 |
| 在代码里写死回复话术 | 每改一次要发版，人格无法迭代 |
| 把权限判断交给模型 | 模型不知道谁是谁，也不知道该不该 |
| 用提示词实现"只读模式" | 真正的只读是工具不给，不是嘴上说 |
| 策略散落在 N 个插件的 if 里 | 后台看不见，用户改不了，冲突无法解释 |

## 5. 内嵌 harness 改变了什么

你提到青梅自己会跑一个 DeepSeek Harness。这件事对规则分层的影响很直接：

```text
┌──────────────── 青梅（治理层，A + B）────────────────┐
│ 会话画像 → 策略求值 → PolicyEnvelope                 │
│ 记忆召回（已按 audience 裁剪）                        │
│ 工具清单（已按策略裁剪）                              │
└───────────────────────┬──────────────────────────────┘
                        │ ACP：把"被裁剪过的世界"交给它
┌───────────────────────▼──────────────────────────────┐
│ 内嵌 DSH（推理层，C）                                 │
│ 人格 / 语气 / 拆解方式 / 追问策略 —— 全是 prompt 与技能 │
└───────────────────────┬──────────────────────────────┘
                        │ 输出
┌───────────────────────▼──────────────────────────────┐
│ 后置校验（A）→ 渠道                                  │
└──────────────────────────────────────────────────────┘
```

结论：

- **C 类不再需要写进青梅的代码**，可以做成 DSH 的人格包、技能包、插件配置。
  改语气 = 改一个 Markdown，不用发版。
- **A/B 仍然必须在青梅进程里**，因为它们是"决策之前的裁剪"。放进 DSH 的 prompt
  就等于把门锁交给屋里的人。
- 青梅的代码量因此显著下降：从"实现一个 agent"，变成"实现一个信封 + 一个治理层"。

这也是 [07](07-Harness协作协议.md) 里"青梅自己也是 harness 的使用者"的延伸——
它不只借 harness 修自己，也借 harness 思考。

**记忆热点打分、夜间整理、周报措辞、主动消息的措辞，全部是 C 类**，交给内嵌 DSH。
但它们外面必须包三层 A 类约束：单次调整幅度上限、批量降层比例上限、"删除只降层不真删"。
没有这三条，一个月后你会发现重要记忆被淡化光了，而且无法解释是谁干的。

## 6. 可测试性

三类规则的验证方式完全不同，不能混：

| 类 | 测试方式 | 通过标准 |
| --- | --- | --- |
| A | 单元测试 + 属性测试 + 红队用例 | 100% 通过，任何一条不过就是阻塞发布 |
| B | 表驱动：标签 × 意图 → 期望决策 | 规则表全覆盖，冲突优先级可解释 |
| C | 评估集（golden set）+ 人工抽检 | 分数不下降；不追求"全对" |

**C 类必须接受"没有标准答案"**，只能看评分趋势。这也是为什么 A/B 不能混进 C：
一旦混进去，你就无法用断言保护真正的红线。

### 6.1 周期评估：让青梅定期问你

C 类没有断言，唯一的真值是你的判断。所以要有一个固定节奏的"体检"，而不是等你哪天觉得它变笨了。

- **频率**：默认每月一次；可调为每两周 / 每季度，或按"累计 200 轮对话"触发。
- **抽样**：从本周期里抽 12–20 条对话，覆盖工作、闲聊、拒绝、追问四类场景；
  每条展示：场景、你的原话、它的回答、当时生效的策略信封。
- **打分**：1–5 分 + 一句话建议。网页/手机一屏能完成；手表只给 👍/👎 两键。
- **聚合**：按群标签、人格版本、场景类型分别统计，与本周期对比，自动标出回归项。
- **落地**：分数下降 → 生成一条 C 类调整提案（改哪段提示词/技能），走 L1 变更（快照 + 可回滚）；
  你的文字建议直接作为提案依据，而不是存档了事。
- **防打扰**：连续两次不回应就暂停，之后降频；"这次不评"要被记住，不能每月重问。

关键：评分不是目的，**把"你的一句话"变成下一次的改动依据**才是。
只收集不行动的评分，比不做还糟——它会让你误以为系统在变好。

## 7. 变更管理

| 类 | 谁能改 | 怎么生效 | 怎么回滚 |
| --- | --- | --- | --- |
| A | 只有你，发版 | 换版（supervisor，见 08） | 换回旧版本 |
| B | 你在后台 | 立即 | 一键恢复上一版策略 |
| C | 你或自进化（L1） | 下一条消息 | 版本快照，随时回退 |

C 类之所以敢让自进化碰（L1），正是因为它可回滚、可评估、不碰红线。

## 8. 什么时候必须把 C 拉回 B 或 A

出现以下信号，说明"提示词方案"已经不够：

1. **同一类错误重复出现**（比如连续三周在群里说错话）→ 说明判断标准应该显式化 → 转 B。
2. **需要对外举证**（客户问"你们的机器人为什么这么说"）→ 需要确定性 → 转 B。
3. **涉及钱、法务、不可逆操作** → 转 A。
4. **成本失控**（每次都要大模型判一遍）→ 用小规则前置过滤 → 转 B。

## 9. 成本

- 走内嵌 harness，每次对话多一跳（进程间 + 上下文），延迟与成本都高于内联实现。
  换来的是 C 类可以不发版迭代。
- 缓解：短消息/简单确认走轻量路径（不经过 harness），复杂判断才升级；
  但**两条路径必须共用同一个信封**，否则行为会分叉。
- **降级**：内嵌 harness 不可用时（崩溃、超时、模型欠费），青梅退到「固定话术 + 只读查询」，
  不做自由对话。**不要在青梅里再写一套 loop 兜底**——两套行为一定会分叉，
  而且你无法判断哪套在说话。

## 10. 结论

- 「有些规则不用写成代码」成立，但只对 **C 类（表达与判断）** 成立。
- A 类（安全/权限/不可逆）永远写成代码，且要在模型之前生效。
- B 类（场景策略）写成数据，因为你会一直改它。
- 内嵌 DSH 的最大收益不是"少写代码"，而是**把人格与表达的迭代成本降到接近零**；
  代价是评估与观测必须补上，否则你会不知道它为什么变了。
