# 青梅服务与插件清单

> 本清单按 2026-11-11 的代码整理。装配的唯一真源是 `qingmei.yml` / `qingmei.prod.yml`；
> 改完跑 `node scripts/check-config.mjs`，引用了不存在的包会直接失败（部署前还能拦一次）。

## 1. 运行结构

```text
apps/server
  → 读取 qingmei.yml
  → 动态 import 每个插件
  → Cordis 按 inject 等待依赖
  → host-gateway 提供 HTTP/SSE
  → 渠道适配器接入 Web/飞书/QQ
```

当前规模：

```text
核心 packages       22
experimental     1   （qm-review 已装配，但代码仍在 experimental/）
默认插件（dev）    22
生产插件（prod）   22   （dev 去掉 echo、换成 dsh-acp）
生产服务           18
```

本地默认装配 20 项，生产 22 项。本地只有 `provider-llm-echo`；生产没有 LLM，对话与任务都走 DSH。

本地用：

```text
provider-llm-echo
```

生产：不装配 LLM，聊天/任务走 DSH。

## 2. 服务契约（core 中的 Service）

> 当前 core 仍有 LLM/embedding 契约，但默认装配不再加载 LLM provider。

| 服务 | 作用 | 实现 |
|---|---|---|
| `store` | 通用 collection 存储 | `provider-store-sqlite` |
| `channel` | 渠道注册/发送/状态 | `service-channel` |
| `gateway` | HTTP 路由与 SSE publish | `service-gateway` |
| `llm` | 可选文本服务；生产不装配 | `provider-llm-echo`（本地） |
| `embedding` | 可选向量服务 | 默认未装配 |
| `harness` | 执行器适配 | `provider-dsh-acp`（生产） |
| `memory` | 神经元记忆召回/写入/摘要/重放 | `provider-neuron-memory` |
| `history` | `qm_message` 读取 | `qm-history` |
| `persona` | 人格加载/热更新/回滚 | `service-persona` |
| `thread` | 跨端 Thread | `qm-history` |
| `task` | 任务账本 | `qm-task`（账本 + 调度在同一插件里） |
| `taskTargets` | 解析 executor/workarea/sessionKey | `qm-device` |
| `taskRunner` | 本地执行与远程 lease 调度 | `qm-task` |
| `identity` | 渠道身份/owner 绑定 | `qm-identity` |
| `conversationProfile` | 群画像/策略 | `qm-conversation-profile` |
| `skills` | 技能包读写 | `qm-skill` |
| `approval` | 审批创建/等待/决定 | `qm-approval` |
| `channelTargets` | 最近渠道目标 | `qm-approval` |
| `autonomy` | 主动循环状态 | `qm-autonomy` |

`service-channel` / `service-gateway` / `service-persona` 是运行时服务；契约在 core。

## 6. DSH / LLM / 执行器边界

```text
DSH harness
  = 执行器
  = 本地 provider-dsh-acp 或设备 companion
  = 有自己的模型、工具、会话

LLM service
  = 青梅内部结构化文本工具
  = 记忆抽取、digest、lessons
  = 目前 qm-agent 仍保留 LLM 对话回退
```

当前 `TaskTarget.executorId`：

```text
local
  → qm-task TaskRunner
  → provider-dsh-acp

device:<id>
  → qm-device TaskTargetService 解析
  → 设备 companion claim
  → 本机 DSH Host
```

## 8. 客户端与外部程序

```text
apps/web        Vue 3 Web；HTTP + SSE
apps/desktop    Electron 壳 + renderer + 安装器
apps/mobile     Capacitor Android WebView
apps/dsh-companion  设备 worker，运行在 DSH Host
apps/dsh-hook   DSH 会话 ingest hook
apps/server     组合根
```

`apps/dsh-companion` 不是独立执行器模型；它只是把设备 DSH 注册为 `device:<id>` 执行器并 claim 任务。

## 9. 当前关键边界

1. `qm-agent` 仍是对话入口，不是单纯执行器；它还没有完全 Task 化。
2. `provider-dsh-acp` 是本地执行器，设备 companion 是远程执行器；两者共用 `TaskTarget` 与 `TaskRunner.lease` 调度。
3. `LlmService` 仍用于记忆/摘要，且 `qm-agent` 仍有 LLM 对话回退。
4. 设备审批桥和设备上下文组装尚未完全统一。
