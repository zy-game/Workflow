# 09 · 神经元记忆核心

> 记忆是青梅的第二个内核，不是"检索插件"。
> 输入输出谁都会做，**连续性和"它记得我"**才是助理与聊天框的分界线。
> 本文把 [04](04-记忆数据与隐私.md) 的数据与隐私策略，升级成一个有动力学的记忆引擎。

## 1. 为什么不是普通 RAG

普通 RAG：问题 → 向量检索 topK → 塞进 prompt。它有三个硬伤：

| 硬伤 | 后果 | 神经元模型的解法 |
| --- | --- | --- |
| 只按语义相似 | 「咖啡」召不回「失眠」，哪怕它们在你的生活里强相关 | 突触扩散：从种子节点沿关系走 2–3 跳 |
| 无时间结构 | 不知道「先答应、后反悔」的顺序 | 时序突触 + 情节链 |
| 不区分轻重 | 随口一句和重要承诺同权 | 显著度（salience）参与衰减与打分 |
| 不会遗忘 | 越用越臃肿，噪声淹没信号 | 衰减 + 剪枝 + 巩固压缩 |

一句话：**RAG 是查字典，记忆是联想。**

## 2. 神经元与突触

### 2.1 数据结构

```sql
CREATE TABLE qm_neuron (
  id            TEXT PRIMARY KEY,
  kind          TEXT NOT NULL,      -- entity | fact | episode | concept | self
  label         TEXT NOT NULL,      -- 可读标签，用于展示与关键词匹配
  embedding     BLOB,               -- float32[]，可为空（图内节点也能参与扩散）
  salience      REAL NOT NULL,      -- 0..1，重要度：目标相关、情绪强度、用户强调
  activation    REAL NOT NULL DEFAULT 0,
  confidence    REAL NOT NULL,      -- 事实可信度（沿用 04 的语义）
  sensitivity   TEXT NOT NULL,      -- public | private | secret
  last_fired_at INTEGER,
  created_at    INTEGER NOT NULL
);

CREATE TABLE qm_synapse (
  from_id        TEXT NOT NULL REFERENCES qm_neuron(id),
  to_id          TEXT NOT NULL REFERENCES qm_neuron(id),
  kind           TEXT NOT NULL,     -- associative | temporal | causal | contradiction
  weight         REAL NOT NULL,     -- 0..1
  co_activated   INTEGER NOT NULL DEFAULT 0,
  last_fired_at  INTEGER,
  PRIMARY KEY (from_id, to_id)
);
```

节点是"记住的东西"，边是"它们之间的关系"。`contradiction` 是一等公民——
「养猫」和「养狗」之间连一条矛盾边，比把旧的直接删掉更接近人脑，也便于回滚与追溯。

### 2.2 动力学

四个参数控制"记性"：

```text
激活衰减     A(t) = A₀ · e^(−λt),        λ = ln2 / 半衰期
             有效半衰期 = 基础半衰期 × (1 + 2·salience)     // 重要的事忘得慢

扩散         A_j ← γ^d · Σ_i A_i · w_ij,  γ = 0.6, d ≤ 3    // 每跳打折

赫布强化     Δw_ij = η · A_i · A_j − μ · w_ij,  η = 0.02, μ = 0.001
             w 截断在 [0, 1]，每次召回后归一化，防止全局爆炸

剪枝         w < 0.05 且 180 天未被共同激活 → 删除
```

默认值（可配）：长期记忆半衰期 30 天，工作记忆半衰期 2 小时，`salience` 由目标关联、
用户强调（「记住这个」）、情绪强度（连续负面/正面表达）三者合成。

**为什么要有衰减**：不衰减的记忆会变成一堆等权重的噪声，"越用越准"就无从谈起。
遗忘不是缺陷，是信噪比的来源。

## 3. 四层记忆与激活

| 层 | 对应 | 半衰期 | 容量 | 参与注入 |
| --- | --- | --- | --- | --- |
| **感觉缓冲** | 最近 1–2 轮原始输入 | 分钟 | 极小 | 全量 |
| **工作记忆** | 当前会话的活跃节点集（约 7±2 个组块） | 小时 | 有限 | 高权重 |
| **长期记忆** | 情节 + 事实 + 概念 | 周到月 | 万级 | 按召回 |
| **自我模型** | 身份、价值、关系史、当前聚焦 | 不衰减 | 一份 | 常驻 |

工作记忆不是一个列表，而是**当前被点亮的神经元集合**。每轮对话开始时继承上一轮未衰减完的激活，
这让「他刚说的那个」不需要重复指代。

自我模型是唯一不参与衰减的层：它是"青梅是谁"，不是"青梅经历过什么"。

**这四层是全局的，不是每端一份。** 记忆中枢只有一个；PC、手机、QQ、飞书、Watch、harness
都是它的视口与生产者，端上只允许有缓存。跨端如何合并、去重、缝合任务，见
[10 · 跨端统一记忆](10-跨端统一记忆.md)。

## 4. 召回：种子 → 扩散 → 重排 → 预算

```text
查询（当前消息 + 最近 2 轮）
  │
  ├─1 种子：向量 topK 20 + FTS topK 20 + 工作记忆中的活跃节点 → 合并去重
  ├─2 扩散：按 synapse 走 ≤3 跳，A_j 累加，γ 逐跳衰减
  ├─3 硬过滤：scope / 敏感度 / 有效期 / 渠道（群聊不注入私事）
  ├─4 打分：
  │     score = 0.35·相似度 + 0.25·激活 + 0.20·置信度
  │           + 0.10·时效   + 0.10·显著度
  ├─5 重排：用小模型（或同一次调用）对 top 30 做一次相关性判断，砍掉"语义像但无关"的
  └─6 预算：按 score 降序装入 prompt，到 token 预算为止
```

第 5 步不是可选项。扩散会带来"联想过度"——把「咖啡」连到「失眠」是对的，
连到「咖啡机维修」就是噪声。小模型重排是这道闸。

**召回必须无副作用**（不在 `recall` 里改权重）。权重更新放在召回结束后异步进行，
否则一次查询会污染记忆。

## 5. 巩固：睡眠期

人脑靠睡眠把短期经历固化成长记忆，青梅靠空闲期的批处理做同样的事。默认每天一次，
在低峰时段（学习用户的活跃曲线后自动选时）。

```text
① 聚类      把过去 24h 的情节按 embedding + 时间邻近聚成若干"事件"
② 抽取      每个事件抽候选事实（沿用 04 的门槛与去重）
③ 合并      语义重复的神经元合并；保留更可信、更晚的那条，另一条连线到它
④ 强化      同一事件内共同激活的节点，w += 0.05（有上限）
⑤ 剪枝      弱边删除；孤立且低显著的节点降到冷存储
⑥ 冲突      同 (subject, predicate) 不同 object → 建 contradiction 边，旧值置 valid_to
⑦ 自我模型  每周重算一次"关系史摘要"与"当前聚焦"，人工可编辑
⑧ 压缩      表整理、向量重排、索引重建
```

巩固过程必须**可中断、可重入**：中途崩溃不能留下半合并的状态，每一步用事务包起来。

## 6. 遗忘、冲突与污染

| 情况 | 处理 |
| --- | --- |
| 自然衰减 | 权重与激活降到阈值以下 → 冷存储 → 最终删除（可由用户恢复 30 天） |
| 用户说「忘掉」 | 真删：神经元、突触、FTS 行、向量一并清理，写审计 |
| 事实矛盾 | 不删旧的，建 `contradiction` 边，旧值 `valid_to`；召回时新的优先，但旧的可追溯 |
| 记忆污染 | 低置信事实被反复召回会自我强化——所以**召回不加固**，只有"被用户确认"或"与其他证据一致"才提升置信度 |
| 错误强化 | 同一事实连续 3 次被用户纠正 → 置信度归零并进入待人工复核队列 |

**污染是这套设计最大的风险**：模型抽错一条事实，如果召回时又给它加权，它会越来越"真"。
因此：召回只读、置信度只由外部证据提升、用户纠错有最高优先级。

## 7. 人格化：模型 + 记忆 + 自我模型

只靠系统提示词做人格，得到的是一张脸谱；人格的连续感来自记忆。

```text
┌─ 语言能力（DeepSeek 模型）─────────┐  决定"会说什么"
├─ 记忆（情节 / 事实 / 关系）────────┤  决定"知道什么"
└─ 自我模型（身份 / 价值 / 当前聚焦）─┘  决定"是谁在说"
```

- **模型**负责表达与推理，不做人格存储。换模型不该换人格。
- **记忆**负责具体：「你对花生过敏」「你妈周三生日」。
- **自我模型**负责连贯：青梅怎么称呼自己、边界在哪、这段时间在帮你盯什么。

三者合成后，prompt 里只放**摘要**（自我模型 + 召回结果），不放全量记忆——
这既是成本考虑，也是信噪比考虑。

## 8. 进入核心层意味着什么

记忆从"可插拔服务"升级为"核心层"，代价与约束：

1. **不可热卸载。** `memory` 服务缺失时进程拒绝启动（fail fast），而不是降级成无记忆模式。
2. **迁移只前进。** schema 版本单向递增；回滚版本 = 恢复备份，不做逆向迁移。
3. **模型版本化。** 换 embedding 模型要重建索引（后台任务 + 双写过渡），不能混用空间。
4. **性能红线。** 召回 P95 < 80ms（本地，万级节点）；巩固限流，不与对话争 CPU。
5. **降级链**：向量不可用 → FTS + 图扩散；图不可用 → 纯向量；全部不可用 → 只用工作记忆，
   并且**明确告诉用户"我今天记性不好"**，而不是假装记得。
6. **可解释。** 每条被注入的记忆都能回答「为什么它出现了」（哪条边、哪一跳、多少分）。
7. **全局唯一。** 只有一个写入入口 `memory.ingest()`，端侧不得直写本地库；
   多端、多渠道、harness 上报全部经此收敛（见 [10](10-跨端统一记忆.md)）。

## 10. 指标与验收

| 指标 | 定义 | 目标 |
| --- | --- | --- |
| 召回准确率 | 人工标注 200 条查询的 top5 命中率 | ≥ 85% |
| 误忆率 | 把 A 的事安到 B 身上的比例 | ≤ 2% |
| 巩固冗余率 | 巩固后语义重复的事实占比 | ≤ 5% |
| 用户纠错频次 | 每周"记错了"的次数 | 逐月下降 |
| 召回延迟 | P95 | < 80ms |
| playbook 命中率 | 自修复中命中已知问题的比例（与 08 联动） | 6 个月后 ≥ 40% |

验收方式：**冷启动测试**——全新环境，导入三个月真实对话，问 20 个只有长期记忆才能答对的问题。

## 11. 风险

| 风险 | 说明 | 对策 |
| --- | --- | --- |
| 记忆污染 | 错事实被反复强化 | 召回只读；置信度只由外部证据提升；纠错优先 |
| 联想过度 | 扩散把无关内容拉进来 | 小模型重排 + 跳数上限 + 剪枝 |
| 成本 | 每次召回都做重排与扩散 | 工作记忆命中优先；重排只对 top30；缓存 |
| 冷启动 | 新装用户没有记忆，体验差 | 前两周用"主动提问式建档"补齐画像 |
| 隐私 | 记忆越全，泄露面越大 | 沿用 04 的敏感度矩阵；secret 不进云；群聊不注入 |
| 自我强化偏差 | 只记得同意自己的话 | 主动保留反例与否定记忆，巩固时不得只聚类正面事件 |
