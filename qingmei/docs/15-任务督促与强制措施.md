# 15 · 任务督促与强制措施

> 提醒之所以没用，是因为它没有后果。
> 督促的设计目标不是"逼你"，是让**承诺和现实对齐**——要么推进，要么诚实地改期。

## 1. 从提醒到督促

| 层级 | 形态 | 用户的感受 | 有效性 |
| --- | --- | --- | --- |
| 提醒 | 「任务 X 明天到期」 | 知道了，然后忽略 | 低 |
| 督促 | 「你今天在群里 47 条，任务 0 进展；要我帮你重排，还是现在做 30 分钟？」 | 有点烦，但被说中 | 中 |
| 后果 | 强制专注模式、关闭娱乐应用、锁屏 | 真的疼 | 高（但危险） |

青梅要的是第二层，第三层只在**你事先授权**的前提下使用。

## 2. 合同先行

没有合同的强制就是霸凌。创建任务时就要写清三件事：

```ts
interface TaskContract {
  taskId: string
  deadline: Date
  /** 什么算"有进展"——不能靠模型主观判断 */
  progressSignal: 'harness-run' | 'self-report' | 'artifact' | 'milestone'
  /** 期望进度曲线：按天/按半天 */
  expected: { at: Date; percent: number }[]
  /** 授权强度：决定最多能升到哪一级 */
  enforcement: 'nudge' | 'firm' | 'strict' | 'contract'
  /** 强制手段白名单（strict 及以上才需要） */
  allowedActions: ('focus-mode' | 'block-apps' | 'close-chat' | 'lock-screen' | 'notify-partner')[]
  /** 逃生条款：一次可无理由暂停 N 小时 */
  escape: { perDay: number; hours: number }
}
```

四个强度：

| 强度 | 最多升到 | 适合 |
| --- | --- | --- |
| `nudge` | L1 提醒 | 杂事、低优先 |
| `firm` | L2 要求重排/计划 | 一般任务 |
| `strict` | L3 摩擦（专注模式/屏蔽） | 有截止日的重要任务 |
| `contract` | L4 强制（关聊天/锁屏） | 你自己要求的硬承诺 |

**默认 `firm`**。不默认强制，因为强制很容易变成自我惩罚。

## 3. 怎么知道"在水群"

判定必须**可解释**：先给事实，再给话。不能只有"我觉得你在摸鱼"。

| 信号 | 来源 | 可得性 | 隐私 |
| --- | --- | --- | --- |
| 群消息条数 | 机器人所在的群（QQ/飞书事件） | 高 | 只统计条数，不读内容 |
| 前台应用 | PC 客户端（可选） | 中（需授权） | 只记应用名与时长 |
| 空闲时长 | PC 客户端 | 高 | 本地聚合 |
| 任务进展 | harness 汇报 / 自报 / 产物 | 高 | — |
| 屏幕使用时长 | Android 使用情况 API | 中（需授权） | 只记分应用时长 |
| 位置/日程 | 日历 | 高 | — |

默认只开**低侵入**的两项：群消息条数 + 任务进展。其余需要你在设置里逐项打开。

判定输出是一份事实清单，不是结论：

```json
{
  "window": "今日 09:00–15:00",
  "facts": [
    "群消息 47 条（其中闲聊群 42 条）",
    "任务 X 进展 0%，期望 50%",
    "无 harness 会话",
    "PC 前台 3.5 小时为聊天/视频应用"
  ],
  "verdict": "behind"
}
```

模型只负责把这份清单说成人话，不负责定罪。

## 4. 升级阶梯

```text
L0 上下文提示   在对话里顺带一句（不单独发消息）
L1 私聊提醒     带事实清单 + 一个可执行选项
L2 要求决策     重排期 / 降范围 / 现在做 30 分钟（三选一，必须回）
L3 摩擦         专注模式、屏蔽娱乐站点/应用、关闭聊天窗口
L4 强制         强制下线 PC QQ、手机锁屏（需 contract 强度 + 白名单）
```

升级条件（同时满足才升，避免误判连环轰炸）：

| 升级 | 条件 | 冷却 |
| --- | --- | --- |
| L0→L1 | 落后 >20% 且 1 小时无进展 | 3 小时 |
| L1→L2 | 落后 >40%，或连续 2 次 L1 无回应 | 6 小时 |
| L2→L3 | 落后 >60% 且距截止 <8 小时，且 L2 未回应 | 12 小时 |
| L3→L4 | 已逾期，且契约为 `contract`，且用户未改期 | 每任务每日 1 次 |

**降级**：任何一次真实进展（harness 运行 / 自报 / 产物）都立刻回落到 L1 并重置冷却。
督促不是惩罚记录，是状态机——你一动，它就松。

## 5. 优先级决定阶梯深度

| 优先级 | 默认强度 | 最高级别 | 说明 |
| --- | --- | --- | --- |
| P0 | strict | L4 | 有外部承诺（客户、发布日） |
| P1 | firm | L3 | 有明确截止 |
| P2 | firm | L2 | 有目标无硬截止 |
| P3 | nudge | L1 | 想法、备忘 |

优先级可以随时改，但**升级不会因为改优先级而追溯豁免**——已经升到的级别只降不升。

## 6. 强制手段的可行性

| 手段 | PC (Windows) | Android | iOS | 备注 |
| --- | --- | --- | --- | --- |
| 专注模式 / 勿扰 | ✅ 系统 API | ✅ | ✅（快捷指令） | 最温和，优先用 |
| 屏蔽娱乐站点 | ✅ hosts/代理 | ⚠️ 需 VPN 或无障碍 | ❌ | 易被绕过，属"摩擦"不属"强制" |
| 关闭聊天窗口 | ✅ 结束进程 | ⚠️ 无障碍 | ❌ | 可被重开，需配合重复检查 |
| 强制下线 QQ | ⚠️ 结束进程（非注销） | ❌ | ❌ | 只能做到"关掉"，用户能重登 |
| 手机锁屏 | — | ✅ 设备管理员 | ❌ | 需用户授权；紧急电话仍可用 |
| 全屏遮罩 | ✅ | ✅ | ❌ | 最可控的"强制感" |

**现实结论**：真正的"强制下线/锁屏"只在 Windows 与 Android（且需授权）上可行，
而且都能被重启绕过。所以定位要诚实：**它制造摩擦，不制造不可能**。

## 7. 安全与伦理

六条硬规则，写进代码：

1. **只对自己**：任何强制动作只能作用于 owner 的设备，永不作用于他人。
2. **失效安全**：执行器崩溃、服务不可达时必须放行，绝不能把人锁在系统外。
3. **逃生条款**：任何强制有一个 30 秒可取消窗口 + 每日 N 次无理由豁免（默认 1 次）。
4. **不羞辱**：措辞用事实 + 选择，不用"你又""总是""果然"。
5. **可审计**：每次升级/强制记录触发事实、理由、持续时间。
6. **不做医学建议**：作息与休息参数是**可配置默认值**，不是健康指导。

## 8. 休息侧：同样的机制反过来用

只逼不歇，两周就崩。休息与工作用同一套阶梯，方向相反：

| 触发 | 动作 | 依据（诚实标注） |
| --- | --- | --- |
| 连续专注 90 分钟 | 建议 10–15 分钟离开屏幕 | 超日节律（流行说法，证据一般） |
| 连续 2 个周期忽略休息 | 强制 5 分钟遮罩 | 同上，属于习惯设计而非医学结论 |
| 23:30 后仍在工作 | 提醒收工；`contract` 强度可锁屏 | 睡眠与次日认知表现相关（证据较强） |
| 连续工作 >6 天 | 建议安排一天低强度 | 恢复需求（经验规则） |

把这些参数做成可配置，并在界面上写清"这是默认值，不是医学建议"。
**不要用"科学证明"来包装一个产品选择**——那既不诚实，也会在被质疑时崩掉。

## 9. 失败模式

| 失败 | 表现 | 对策 |
| --- | --- | --- |
| 误判 | 你在开会，被判"无进展" | 日历忙闲优先于活动信号；会议中不升级 |
| 逼反 | 越催越不想做 | 提供"改期/降范围"出口；L2 必须给三个选项 |
| 循环升级 | 无回应就一路升到锁屏 | 每级冷却 + 每日上限 + 连续 2 次忽略后停止并转人工沟通 |
| 把自己锁死 | 执行器崩了还拦着 | 失效安全 + 独立 watchdog |
| 数据失真 | 群消息统计把机器人自己算进去 | 只统计 owner 的消息；排除 bot |

## 10. 指标

| 指标 | 目标 |
| --- | --- |
| L1 后 2 小时内恢复进展的比例 | ≥ 40% |
| L3 触发率（占任务数） | ≤ 10%（太高说明排期不现实） |
| 误判申诉率 | ≤ 5% |
| 强制后仍逾期 | 逐月下降 |
| 强制动作失败率（该做没做） | ≤ 1% |
| 用户关闭督促的比例 | ≤ 2%/月（高了说明太吵） |

## 11. 里程碑

| 阶段 | 内容 | 工期 | 验收 |
| --- | --- | --- | --- |
| **W1** | 任务合同 + 进展定义 + 事实清单 | 1.5 周 | 创建任务时能选强度与进展信号；事实清单可解释 |
| **W2** | L0–L2 阶梯 + 冷却 + 降级 | 2 周 | 落后 20% 触发 L1；有进展立刻回落 |
| **W3** | L3 摩擦（专注模式/遮罩/屏蔽） | 2 周 | 只对白名单生效；30 秒可取消 |
| **W4** | L4 强制（PC 关聊天 / Android 锁屏）+ 逃生条款 | 2 周 | 失效安全通过演练；每日上限生效 |
| **W5** | 休息侧（休息提醒/收工/周恢复） | 1 周 | 90 分钟节律可配；夜间收工生效 |

W1–W2 是主体，约 3.5 周；W3–W4 是"真强制"，建议做完 W1–W2 观察一个月再上，
否则你会先被自己的督促系统烦到关掉它。

## 12. 放 future 的部分

- iOS 的任何强制（沙盒不允许；只能引导用户自建快捷指令）
- 真正的"注销 QQ 账号"（不现实，也不该由助理做）
- 跨设备统一锁屏（需要厂商级权限）
- 智能硬件联动（手环检测睡眠、体重秤、门锁）——见 [16](16-Future与硬件依赖.md)
