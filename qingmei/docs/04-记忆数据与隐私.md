# 04 · 记忆、数据与隐私

> **修订提示**：本文的数据表、敏感度分级、出网矩阵与备份策略仍然有效。
> **记忆的分层与召回机制已被 [09 · 神经元记忆核心](09-神经元记忆核心.md) 取代**：
> 从「L0–L3 四层」改为「神经元图 + 工作记忆 / 长期记忆 / 自我模型 + 激活动力学」。
> 本文的 `qm_mem_fact` / `qm_mem_episode` 保留为人工可读的投影视图，引擎内部以 `qm_neuron` / `qm_synapse` 为准。

个人助理的价值密度全在记忆上。记不住，就只是个聊天框；记错了、记漏了、或者把私事送到云上，
比没有更糟。本文档定义数据从哪来、放哪、怎么被找回来、以及什么绝对不出门。

## 1. 存储形态

| 形态 | 用途 | 实现 |
| --- | --- | --- |
| 关系库 | 会话、消息、事实、日程、审计 | SQLite（WAL）单文件 `data/qm.db` |
| 全文索引 | 事实与消息的关键词召回 | SQLite FTS5，`unicode61` 分词 |
| 向量索引 | 语义召回 | `sqlite-vec` 扩展；不可用时退化为暴力余弦（< 1 万条足够） |
| 文件 | 图片、语音、附件 | `data/blobs/<yy>/<mm>/<hash>`，内容寻址 |
| 配置 | 非敏感设置 | `qingmei.yml` + `data/state/*.json`（插件状态） |

**不上数据库服务器**。单用户场景引入 Postgres 只会增加运维成本；
`store` 服务保留 Postgres 提供方的接口兼容性，但不作为默认。

## 2. 表结构草案

```sql
-- 人
CREATE TABLE qm_actor (
  id            TEXT PRIMARY KEY,            -- 'owner' | 'actor_<ulid>'
  display_name  TEXT NOT NULL,
  role          TEXT NOT NULL,               -- owner | family | guest | stranger
  created_at    INTEGER NOT NULL
);

CREATE TABLE qm_channel_identity (
  platform         TEXT NOT NULL,            -- 'qq' | 'feishu'
  platform_user_id TEXT NOT NULL,
  actor_id         TEXT NOT NULL REFERENCES qm_actor(id),
  verified_at      INTEGER,                  -- 双通道验证时间，NULL 表示未验证
  PRIMARY KEY (platform, platform_user_id)
);

-- 会话
CREATE TABLE qm_conversation (
  id                       TEXT PRIMARY KEY,
  channel                  TEXT NOT NULL,
  platform_conversation_id TEXT NOT NULL,
  kind                     TEXT NOT NULL,    -- dm | group | thread
  title                    TEXT,
  created_at               INTEGER NOT NULL,
  UNIQUE (channel, platform_conversation_id)
);

CREATE TABLE qm_session (
  id             TEXT PRIMARY KEY,
  conversation_id TEXT NOT NULL REFERENCES qm_conversation(id),
  actor_id       TEXT REFERENCES qm_actor(id),
  persona_id     TEXT NOT NULL,
  title          TEXT,
  summary        TEXT,                       -- L0 滚动摘要
  summary_up_to  TEXT,                       -- 摘要覆盖到的消息 id
  created_at     INTEGER NOT NULL,
  archived_at    INTEGER
);

-- 消息与回合
CREATE TABLE qm_message (
  id                 TEXT PRIMARY KEY,
  session_id         TEXT NOT NULL REFERENCES qm_session(id),
  role               TEXT NOT NULL,          -- user | assistant | system | tool
  direction          TEXT NOT NULL,          -- in | out
  blocks_json        TEXT NOT NULL,          -- Block[]
  platform_message_id TEXT,
  trace_id           TEXT,
  created_at         INTEGER NOT NULL
);
CREATE UNIQUE INDEX qm_message_idem ON qm_message(session_id, platform_message_id)
  WHERE platform_message_id IS NOT NULL;
CREATE INDEX qm_message_timeline ON qm_message(session_id, created_at);

CREATE TABLE qm_turn (
  id           TEXT PRIMARY KEY,
  session_id   TEXT NOT NULL REFERENCES qm_session(id),
  status       TEXT NOT NULL,                -- ok | partial | failed | aborted
  steps        INTEGER NOT NULL DEFAULT 0,   -- 工具循环轮数
  tokens_in    INTEGER,
  tokens_out   INTEGER,
  latency_ms   INTEGER,
  error_code   TEXT,
  created_at   INTEGER NOT NULL
);

-- 记忆：L2 事实 / L1 情节 / L3 画像
CREATE TABLE qm_mem_fact (
  id            TEXT PRIMARY KEY,
  subject       TEXT NOT NULL,               -- 'actor:owner' | 'project:qingmei' | 'thing:咖啡'
  predicate     TEXT NOT NULL,               -- '喜欢' | '截止于' | '居住在'
  object        TEXT NOT NULL,
  scope         TEXT NOT NULL,               -- global | actor | group | project
  scope_id      TEXT,
  confidence    REAL NOT NULL,               -- 0..1
  sensitivity   TEXT NOT NULL,               -- public | private | secret
  source_type   TEXT NOT NULL,               -- message | manual | tool | import
  source_id     TEXT,
  valid_from    INTEGER NOT NULL,
  valid_to      INTEGER,                     -- NULL = 仍然有效
  created_at    INTEGER NOT NULL
);
CREATE INDEX qm_fact_live ON qm_mem_fact(subject, predicate) WHERE valid_to IS NULL;
CREATE INDEX qm_fact_scope ON qm_mem_fact(scope, scope_id, valid_to);

CREATE VIRTUAL TABLE qm_fact_fts USING fts5(
  subject, predicate, object, content='qm_mem_fact', content_rowid='rowid'
);

CREATE TABLE qm_mem_episode (
  id          TEXT PRIMARY KEY,
  session_id  TEXT NOT NULL,
  at          INTEGER NOT NULL,
  summary     TEXT NOT NULL,                 -- 一段经历的浓缩描述
  actors      TEXT,                          -- JSON: 涉及的人
  sensitivity TEXT NOT NULL,
  embedding   BLOB                           -- float32[]，可空
);

CREATE TABLE qm_profile (
  actor_id   TEXT NOT NULL REFERENCES qm_actor(id),
  key        TEXT NOT NULL,                  -- '作息' | '偏好食物' | '沟通风格'
  value      TEXT NOT NULL,
  confidence REAL NOT NULL,
  updated_at INTEGER NOT NULL,
  PRIMARY KEY (actor_id, key)
);

-- 日程 / 任务 / 目标
CREATE TABLE qm_schedule (
  id            TEXT PRIMARY KEY,
  owner_id      TEXT NOT NULL,
  kind          TEXT NOT NULL,               -- at | every | cron
  spec_json     TEXT NOT NULL,
  payload_json  TEXT NOT NULL,
  next_at       INTEGER,
  last_fired_at INTEGER,
  missed_policy TEXT NOT NULL,               -- fire-once | skip
  paused        INTEGER NOT NULL DEFAULT 0,
  created_at    INTEGER NOT NULL
);
CREATE INDEX qm_schedule_next ON qm_schedule(next_at) WHERE paused = 0;

CREATE TABLE qm_task (
  id          TEXT PRIMARY KEY,
  owner_id    TEXT NOT NULL,
  title       TEXT NOT NULL,
  detail      TEXT,
  status      TEXT NOT NULL,                 -- todo | doing | done | dropped
  due_at      INTEGER,
  project     TEXT,
  created_at  INTEGER NOT NULL,
  updated_at  INTEGER NOT NULL

CREATE TABLE qm_goal (

  title      TEXT NOT NULL,

  created_at INTEGER NOT NULL

-- 审计 / 插件状态 / 凭据引用
CREATE TABLE qm_audit (
```

## 3. 记忆四层

| 层 | 内容 | 生命周期 | 注入方式 |
| --- | --- | --- | --- |
| **L0 工作记忆** | 当前会话最近 N 轮 + 滚动摘要 | 会话内 | 直接进 prompt（占 40% 预算） |
| **L1 情节记忆** | 「上周三你和小林讨论了行程」这类经历 | 90 天热存，之后归档 | 命中才注入摘要（占 25%） |
| **L2 事实记忆** | 原子事实：喜好、关系、约束、日期 | 长期，有 `valid_to` | 召回后按条注入（占 25%） |
| **L3 画像记忆** | 作息、价值观、沟通偏好、关系史 | 长期，人工可改 | 常驻系统提示（占 10%） |

层的意义不是学术分类，而是**控制注入预算**：L0 保证连贯，L2 保证准确，L3 保证「像一个人」。

## 4. 写入流水线

```text
qm/turn/end
   │
   ├─1 抽取：llm.complete({ purpose: 'extract', sensitivity: 同原消息 })
   │        输出候选事实 JSON（subject/predicate/object/confidence）
   ├─2 归一：'我' → 'actor:owner'；别名 → 规范实体（人/项目/物品）
   ├─3 去重：完全相同的 (subject,predicate,object) 只更新 confidence 与时间
   ├─4 冲突：同 (subject,predicate) 不同 object
   │        → 新值写入，旧值 valid_to = now（不删除，保留可追溯）
   ├─5 门槛：confidence < 0.6 的候选进「待确认」，不直接生效
   └─6 落库：mem_fact + 发 qm/memory/committed
```

纪律：

- 抽取在**回复之后异步执行**，任何失败只记日志，不影响对话。
- 抽取模型可以是小模型（成本低），但**敏感消息必须用本地模型抽取**，否则内容先出网了就失去意义。
- 用户显式说「记住……」「以后都……」的事实，`confidence = 1.0` 且 `source_type = manual`。
- 事实写库必须带 `source_id`（哪条消息来的），否则视为缺陷——无法追溯的记忆等于谣言。

## 5. 召回流水线

```text
当前消息 + 最近 3 轮
   │
   ├─1 查询构造：抽取关键词 + 向量化
   ├─2 候选召回：FTS5 topK 30 + 向量 topK 30，去重合并
   ├─3 硬过滤：scope 不匹配 / 权限不允许 / sensitivity 超过当前渠道 / valid_to 已过期
   ├─4 打分：
   │     score = 0.50 × 语义相似度
   │           + 0.20 × 置信度
   │           + 0.15 × 时效衰减（半衰期 90 天）
   │           + 0.10 × 作用域加成（本会话 > 同 actor > 全局）
   │           + 0.05 × 显式重要度（用户标记 / 长期目标关联）
   ├─5 预算截断：按 score 降序，直到 token 预算用尽
   └─6 格式化：事实转「- 主体 关系 客体（来源：…）」；情节转一句话摘要
```

**召回必须无副作用**：不在 `recall` 里更新「命中次数」之类的字段，统计走 `audit`。

## 6. 冲突、时效与遗忘

| 情况 | 处理 |
| --- | --- |
| 新事实与旧事实矛盾 | 旧记录 `valid_to = now`，新记录 `valid_from = now`；两条都保留 |
| 事实有明确期限（「下周三截止」） | 到期自动 `valid_to`，并产生一条待办提醒 |
| 用户说「忘掉 X」 | 按 `subject/predicate` 批量 `valid_to = now` + 删除 FTS 行；写审计 |
| 敏感级升级（从 private → secret） | 历史低置信记录删除，高置信记录保留但加解密 |
| 情节过期 | 90 天后摘要进冷归档，原消息保留但不再参与召回 |

「忘记」必须是**真删**：FTS 行、向量、blob 一并清理，不能只在查询里过滤。

## 7. 敏感度与出网矩阵

三个等级，定义的是**流转许可**，不是加密强度：

| 数据 | 本地存储 | 云 LLM prompt | 渠道出站 | 审计记录 |
| --- | --- | --- | --- | --- |
| `public`（公开信息、公共知识） | ✓ | ✓ | ✓ | 全文 |
| `private`（个人日程、偏好、工作内容） | ✓ | 仅当路由到允许的 provider | 仅本人私聊/主渠道 | 摘要 |
| `secret`（证件号、健康、财务、密码提示） | ✓ 加密 | ✗ 一律不进云 | ✗ | 仅「发生过一次读取」 |

落地规则：

1. `sensitivity` 在**消息入站**时判定（规则 + 模型），结果写入 `qm_message` 的元数据。
2. 组装 prompt 时，任一 `secret` 片段 → 整个 turn 强制路由到本地模型（`qm-llm-router` 的 `secret` 路由）。
3. 本地模型不可用时**不是降级到云**，而是明确告诉用户：「这句话涉及敏感内容，需要本地模型」。
4. 渠道出站前做 PII 扫描（手机号、证件、银行卡），命中则**阻断并提示**，不静默打码。
5. 群聊场景：`private`/`secret` 记忆一律不注入，默认 `public` 人格。

## 8. 备份、迁移、多设备

- **备份**：`qm backup --out ./qingmei-2026-10-30.qmbak`
  = 在线 `VACUUM INTO` 快照 + blob 清单 + 配置（**不含密钥**），整体加密。
- **恢复**：`qm restore <file>`，恢复前自动备份现有库。
- **迁移**：编号 SQL 文件，启动时按序应用并写 `qm_migration`；已应用的迁移禁止修改（校验 checksum）。
- **多设备**：v1 只做**单向快照**（导出 → 另一台导入），不做实时同步。
  实时同步需要事件日志 + 冲突合并，属于 v2 的 `service-sync`，不在首版承诺范围内。

## 9. 体积与性能

| 数据 | 量级 | 估算 |
| --- | --- | --- |
| 消息 | 1 万条（约 3 个月） | ≈ 15 MB |
| 事实 | 1 万条 + 768 维向量 | ≈ 3 MB + 30 MB |
| 情节 | 1 千条 | ≈ 5 MB |
| 审计 | 每天 500 条 | ≈ 1 MB / 月 |

结论：**单文件 + 单进程完全够用**。当真到 GB 级（多年使用），再上归档分区，
而不是提前上分布式存储。
