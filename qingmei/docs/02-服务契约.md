# 02 · 服务契约

服务是青梅里唯一的横切接口。本文档定义每个服务的**职责、类型签名、事件、错误**。
实现方照此写 provider，消费方照此写调用，双方互不 import。

## 1. 命名空间与拆分判据

- 服务名**全局扁平**（Cordis 的 `Context` 是一个命名空间）。青梅独占进程，直接用短名：
  `llm` `memory` `store` `channel` `schedule` `persona` `tools` `permission` `audit` `identity` `notify` `skills` `gateway`。
- 若青梅被嵌入别的 Cordis 应用（例如作为 DSH 插件），由 `@qingmei/adapter-dsh` 用
  `ctx.isolate()` 做名字空间隔离，**不改业务包**。

**什么时候拆成三个包？** 只有一个判据：*这个角色的实现需要独立演进或替换*。

| 情况 | 怎么做 |
| --- | --- |
| 一种实现，短期不会换 | 一个包同时承担定义和实现（如 `persona`） |
| 需要换实现（库、模型、平台） | 拆 `service-x` + `provider-x-*` |
| 只是把能力暴露给模型 | 单独 `tool-*`，依赖服务即可 |
| 消费者也在演进（呈现方式常变） | 消费者独立成包，依赖定义包 |

**不要预防性拆分。** 一个 30 行的工具插件不需要先建三个包。

## 2. 服务总表

| 服务 | 定义包 | 职责一句话 | 典型提供方 |
| --- | --- | --- | --- |

| `tools` | `service-tools` | 工具注册表与调用封装 | 内置 |
| `schedule` | `service-schedule` | 定时/周期/一次性触发 | 内置（store 支撑） |
| `channel` | `service-channel` | 渠道适配器注册与出站发送 | 内置（适配器为 `channel-*`） |
| `identity` | `service-identity` | 平台身份 ↔ 青梅 actor 的映射与绑定 | 内置 |

| `audit` | `service-audit` | 只追加的审计流水 | 内置（store 支撑） |
| `notify` | `service-notify` | 跨渠道的主动触达路由 | 内置 |
| `skills` | `service-skills` | 技能包的发现与渐进加载 | 内置 |
| `harness` | `service-harness` | 拉起、驱动、回收外部 agent runtime | `harness-acp` / `harness-cli` |

| `gateway` | `service-gateway` | HTTP/SSE/WS 服务与路由注册 | `host-gateway` |

## 3. 契约

> 以下签名是**约定**，实现可加方法，不可改已有方法的语义。
> 所有方法都必须尊重传入的 `AbortSignal`，取消应尽快归还。

> **当前实现（2026-11-02）**：13 个服务有实现——`store` / `llm` / `memory`（fact 子集）/
> `channel` / `gateway` / `schedule` / `task` / `harness` / `mcp` / `permission`（静态策略）/
> `audit` / `approval` / `autonomy`。
> 其余（`persona`、`tools`、`identity`、`conversation`、`notify`、`skills`、`self`）
> 尚未实现；其中 `tools` 在 ADR-013 之后不再是「青梅内的工具循环」，而是 MCP 工具面
> （见 [07](07-Harness协作协议.md) §4）。

### store

```ts
type Row = { id: string }

export abstract class StoreService extends Service {
  abstract collection<T extends Row>(name: string): Collection<T>
  abstract transaction<T>(fn: (tx: Tx) => Promise<T>): Promise<T>
  abstract migrate(migrations: Migration[]): Promise<void>
}

interface Collection<T> {
  get(id: string): Promise<T | null>
  find(query: Query<T>): Promise<T[]>
  insert(value: Omit<T, 'id'> & { id?: string }): Promise<T>
  update(id: string, patch: Partial<T>): Promise<void>
  delete(id: string): Promise<boolean>
  count(query: Query<T>): Promise<number>
}

interface Query<T> {
  where?: Partial<T>
  order?: { field: keyof T; dir: 'asc' | 'desc' }[]
  limit?: number
  offset?: number
}
```

约束：`store` 不认识任何业务表；业务包自己声明 `Migration[]`，由 `qm-migrate` 插件统一调度。
SQLite 提供方开 WAL，写操作串行化；事务内禁止调用 `llm`（会长时间持锁）。

### llm

```ts
export abstract class LlmService extends Service {
  abstract providers(): LlmProviderInfo[]
  abstract chat(req: ChatRequest, signal: AbortSignal): AsyncIterable<ChatChunk>
  abstract complete(req: ChatRequest, signal: AbortSignal): Promise<ChatResult>
  abstract embed(texts: string[], signal: AbortSignal): Promise<number[][]>
  abstract register(provider: LlmProvider): Disposable
}

interface ChatRequest {
  messages: LlmMessage[]
  model?: string
  tools?: ToolSpec[]
  temperature?: number
  maxTokens?: number
  /** 敏感度：决定路由到哪个 provider，见 04 文档 */
  sensitivity?: 'public' | 'private' | 'secret'
  /** 任务类型，路由用：chat | tool-call | summarize | extract | embed */
  purpose?: string
  signal?: AbortSignal
}

type ChatChunk =
  | { type: 'text'; text: string }
  | { type: 'tool-call'; id: string; name: string; args: unknown }
  | { type: 'usage'; input: number; output: number }
  | { type: 'done'; stopReason: 'end' | 'tool-calls' | 'length' | 'error' }
```

`register()` 返回 disposer，提供方插件卸载时自动摘除。
路由（`qm-llm-router`）是消费方而不是 `llm` 的一部分：它订阅 `llm` 并实现 `purpose/sensitivity → provider` 的映射。

### memory

```ts
export abstract class MemoryService extends Service {
  /** 唯一写入入口：多端、多渠道、harness 上报都走这里 */
  abstract ingest(records: MemoryRecord[], opts?: IngestOptions): Promise<IngestResult>
  abstract recall(query: RecallQuery): Promise<RecallResult>
  abstract forget(selector: FactSelector): Promise<number>
  abstract summarize(sessionId: string): Promise<string>
  abstract profile(actorId: string): Promise<ProfileSnapshot>
}

interface MemoryRecord {
  kind: 'fact' | 'episode' | 'decision' | 'lesson' | 'artifact'
  subject?: string; predicate?: string; object?: string   // fact 用
  text?: string                                           // 其余类型用
  occurredAt?: Date
  origin: { kind: 'channel' | 'harness' | 'self' | 'doc' | 'schedule'; id: string; deviceId?: string }
  audience: 'owner' | 'family' | string                   // 'group:<channel>:<id>' | 'device:<id>'
  confidence: number
  sensitivity: 'public' | 'private' | 'secret'
  /** 幂等键；缺省由服务端按 origin.id + 内容哈希生成 */
  idempotencyKey?: string
  links?: { toKey: string; kind: 'associative' | 'temporal' | 'causal'; weight: number }[]
}

interface IngestResult {
  created: string[]
  merged: string[]        // 命中已存在的事实，只追加 provenance
  rejected: { index: number; reason: string }[]
}

interface RecallQuery {
  text: string
  actorId: string
  scope?: MemoryScope[]
  channel?: 'dm' | 'group'
  /** 当前视口：决定 audience 过滤与呈现预算 */
  viewport?: { channel: ChannelId; deviceId?: string }
  limit?: number
  /** 注入 prompt 的 token 预算，超预算按优先级截断 */
  budget?: number
  includeSensitive?: boolean
}

interface RecallResult {
  facts: Fact[]            // 已按相关度 × 置信度 × 时效排序
  episodes: Episode[]
  tokensUsed: number
  /** 可解释：每个命中为什么出现 */
  why?: { neuronId: string; seed: boolean; hops: number; score: number }[]
}
```

行为约定：`recall` 必须**幂等且无副作用**（可缓存，不可写库）。
`ingest` 负责去重与冲突处理（同 `subject+predicate` 的新值使旧值 `validTo = now`），
且**幂等**：同一 `idempotencyKey` 重复上报只应用一次。
**`memory` 属于核心层**：不可热卸载，缺失时进程拒绝启动；图结构、激活与巩固见
[09 · 神经元记忆核心](09-神经元记忆核心.md)，跨端整合与视口过滤见
[10 · 跨端统一记忆](10-跨端统一记忆.md)。

> **当前实现（2026-11-02）**：`fact` 子集——`ingest` / `recall` / `forget`。
> 已按本节语义收口：同一 `subject+predicate` 的新值让旧值 `validTo = now`（软失效，不删除），
> `audience` 区分 `owner` 与 `group:<channel>:<id>`，群聊视口只注入该群 `public` 事实（private/secret 零注入）；
> 渠道前缀保证不同渠道即使会话 id 撞了也不串味。
> `qm-agent` 把 `memory` 列为必需依赖，缺失时插件不 ACTIVE。
> 仍未做：`idempotencyKey`（重复上报靠三元组合并兜底）、`summarize`、`profile`、
> 情节/决策/教训类型、FTS 与向量（docs/09/10 的范围）。

### tools

```ts
export abstract class ToolsService extends Service {
  abstract register(tool: ToolDefinition): Disposable
  abstract list(filter?: { tag?: string; scope?: 'private' | 'group' }): ToolDefinition[]
```

### harness

```ts
export abstract class HarnessService extends Service {
  abstract attach(id: string, opts: AttachOptions): Promise<HarnessHandle>
  abstract list(): HarnessStatus[]
  /** 注入给每个子会话的 MCP 声明（青梅自己） */
  abstract selfMcp(): McpServerDeclaration
  abstract runs(filter?: { taskId?: string; status?: TaskRunStatus }): Promise<TaskRun[]>
}

interface HarnessHandle {
  id: string
  capabilities: HarnessCapabilities
  newSession(opts: { cwd: string; model?: string; mcpServers: McpServerDeclaration[] }): Promise<HarnessSession>
  dispose(): Promise<void>
}

interface TaskRun {
  id: string
  taskId: string
  harnessId: string
  sessionId: string | null
  cwd: string
  status: 'queued' | 'running' | 'needs_approval' | 'done' | 'failed' | 'cancelled'
  priority: number           // 0–9，越大越先跑；缺省 5
  dependsOn: string[]        // 前置 run id；未完成则排队，前置失败则本任务失败
  // 执行器还提供 cancel(id, reason?)：取消排队/执行中的 run（回滚与抢占用）
  progress: { phase?: string; percent?: number; note?: string; at: Date } | null
  budget: { tokens?: number; ms?: number }
  artifacts: ArtifactRef[]
}
```

约束：

- `attach()` 必须在 `ctx.effect` 内调用，句柄随插件卸载而释放；子进程不得成为孤儿。
- 明确不承诺的能力：操纵 harness 的 GUI、读取其未声明的工作区。
- `cwd` 只能来自青梅分配的 run 目录或用户显式授权的路径。
- 完整协议（ACP 方法、MCP 工具清单、审批桥、注入防护）见
  [07 · Harness 协作协议](07-Harness协作协议.md)。

### schedule

```ts
export interface ScheduleInput {
  text: string
  at?: Date                    // 一次性
  everyMs?: number             // 固定间隔
  cron?: string                // 五段式：分 时 日 月 周
  timezone?: string            // IANA；缺省用 provider 配置的默认时区
  missedPolicy?: 'fire-once' | 'skip'
  channel?: ChannelId
  conversationId?: string
}

export interface SchedulePatch {   // 只给 text 就只改文案；给规则就整体替换并重排
  text?: string
  at?: Date
  everyMs?: number
  cron?: string
  timezone?: string
  missedPolicy?: 'fire-once' | 'skip'
}

export interface Scheduled {
  id: string
  text: string
  channel: ChannelId
  conversationId: string
  nextAt: Date
  everyMs: number | null
  cron: string | null
  timezone: string | null
  missedPolicy: 'fire-once' | 'skip'   // 停机期间错过多次，只补一次
  pausedAt: Date | null                // 非空 = 暂停，tick 跳过
  firedAt: Date | null                 // 一次性行到点后写入（退休标志）；周期行恒为 null
}

export abstract class ScheduleService extends Service {
  abstract create(input: ScheduleInput): Promise<Scheduled>
  abstract list(): Promise<Scheduled[]>
  abstract cancel(id: string): Promise<boolean>
  abstract pause(id: string): Promise<boolean>
  abstract resume(id: string): Promise<boolean>
  abstract update(id: string, patch: SchedulePatch): Promise<Scheduled | null>
}
```

规则语义（`provider-schedule-sqlite` 的实现口径）：

- 三类规则三选一；`cron` 为五段式，周字段 0 与 7 都是周日，日与周同时限定时取「或」。
- 下次触发用 `Intl.DateTimeFormat` 反推 UTC，不手写偏移：夏令时跳过的本地时间不触发，
  重复的本地时间只触发一次。
- 暂停保留 `nextAt` 但不触发；恢复时周期规则从「现在」重排，一次性保持原时间；已结束的行不能恢复/修改。
- 参数问题（内容为空、cron 写错、规则冲突）抛 `InvalidScheduleError`，接口层映射成 400。

到点后 `ctx.emit('qm/schedule/due', scheduled)`，由 `qm-reminder` 负责投递；
会话历史由 `qm-history` 订阅 `qm/outbound`（渠道投递成功后）写入，日程服务不碰 `qm_message`。
**`schedule` 只负责「到点通知」，不负责「怎么打扰」**——职责分离，方便单独测试。

### history（qm_message / qm_turn）

qm-history 是会话历史的**唯一写入方**，消息与回合一概由事件落库，其它插件不直接写表：

| 表 | 写入时机 | 关键列 |
| --- | --- | --- |
| `qm_message` | `qm/turn/start`（用户）、`qm/outbound`（助手/主动消息） | `session_id` / `role` / `direction` / `blocks_json` / `text` / `trace_id` / `platform_message_id` / `created_at` |
| `qm_turn` | `qm/turn/end` | `id`（= `traceId`）/ `session_id` / `status`（`ok` / `failed`）/ `latency_ms` / `created_at` |

幂等：同一 `session_id + platform_message_id` 只写一次（平台重投不会多出一条）——
部分唯一索引 + 写入串行化双保险。`qm_message` 的 `(session_id, created_at)` 与 `qm_turn` 的 
`session_id` 都有表达式二级索引，查询已下推到 SQL。
`text` 是给现有读取方（qm-agent、Web）的冗余列，真源是 `blocks_json`。
P1 用通用 JSON 表存，**没有真实索引**；`steps` / `tokens_*` / `error_code` 暂未采集。

### channel


```ts
interface AutonomyCandidate {
  id: string              // 规则 id，冷却与去重按它
  action: string          // 行动白名单里的动作名，如 notify.self / task.retry
  title: string

  id: string

  trigger: 'tick' | 'manual'

  snapshot: { at: Date; pendingApprovals: number; runningTasks: number; failedTasks: number; upcomingSchedules: number }
  candidates: AutonomyCandidate[]
  chosen: AutonomyCandidate | null

  abstract tick(trigger: 'tick' | 'manual'): Promise<AutonomyTrace>
  abstract list(limit?: number): Promise<AutonomyTrace[]>

}
```

循环按 [13 §3](13-主动性架构.md) 六步：快照 → 候选 → 过滤（授权级别 / 静默时段 / 每日预算 / 冷却）
→ 排序 → 执行/建议 → 记 decision trace。A1 只产生建议，不执行动作。

> **当前实现（2026-11-02）**：`qm-autonomy`（业务编排 + 自己的 `qm_autonomy_trace` /
> `qm_autonomy_state` 集合）。规则候选三条：待确认审批（95）、60 分钟内要触发的日程（80）、
> 24 小时内失败的任务（70，动作 `task.retry`）。过滤：23:00–08:00 静默、每日 3 条预算、
> 同一规则 4 小时冷却；预算与冷却落库，重启不丢；决策账本保留 7 天（`retentionDays`）。
> **信任与降频**：发出去的建议进入「等回应」，`acceptWindowMinutes` 内有入站消息算采纳；
> 过了窗口没人理记一次忽略，同一规则被忽略 `ignoreBeforeSlowdown` 次后冷却翻倍；
> 连续采纳到 `upgradeAfter` 且 `autoUpgrade: true` 才升到 A2（默认只记账，升级要人点头），
> `trustLocked` 可锁死级别（配置文件），`POST /api/v1/autonomy/trust` 可手动设级别/锁死并落库；
> `GET /api/v1/autonomy` 返回 `mode` / `locked` / `trust` / `digest.count`。
> **只进摘要**：同一规则被忽略 `digestAfter`（6）次后不再即时发消息，进 `digest` 队列；
> 每天 `digestHour`（20 点）后最多发一次「📥 今日摘要」；`POST /api/v1/autonomy/digest` 可手动发。
> 选中后过**行动白名单两级闸**（`AUTONOMY_ACTIONS`）：白名单外的动作拒绝；不可逆动作不执行；
> 级别不够（如 A1 遇到 `task.retry`）降级成建议消息；执行结果写进 `execution` 回执
> （`executed` / `suggested` / `skipped` / `failed`，带 runId）。已实现执行器：
> `notify.self`（发到主人私聊，走 `qm_message` 历史）、`task.retry`（A2 起：重建 run 并派发）。
> `GET /api/v1/autonomy`、`POST /api/v1/autonomy/tick`，每次 tick 推 SSE `autonomy-tick`；
> Web「主动」面板列出理由、压制原因与回执。
> **还没做**：A2 的排期器（优先级/时间窗/依赖/抢占/容量）、A3 项目审问、A4 热点打分、
> A5 信任升级/降级（目前级别是配置，不会自动升降）。

## 5. 配置与密钥

- 每个插件导出 `Config`（zod），加载即校验，失败信息必须指明字段路径。
- 密钥只来自环境变量或系统凭据库：`{ $env: 'NAME' }` 或 `{ $credential: 'feishu-app-secret' }`。
- 密钥**不得**进入：日志、审计 detail、插件状态快照、错误堆栈。
- 运行时读取密钥统一走 `secrets` 辅助（后续可作为 `service-secrets` 落地）；provider 内禁止直接 `process.env`。

## 6. 兼容与能力探测

- `service-*` 包带 `export const serviceVersion = 1`；破坏性变更才 +1。
- 提供方在 `package.json` 的 `qingmei.service` 字段声明 `implements`。
- 消费方不假设能力存在：`ctx.llm.providers()` 可能为空数组；空数组时应降级为固定话术而不是抛错。
- 已知的「可选能力」用 `ctx.inject()` 承载，不做运行时 `if`。
