# 02 · 服务契约

服务是青梅里唯一的横切接口。本文档定义每个服务的**职责、类型签名、事件、错误**。
实现方照此写 provider，消费方照此写调用，双方互不 import。

## 1. 命名空间与拆分判据

- 服务名**全局扁平**（Cordis 的 `Context` 是一个命名空间）。青梅独占进程，直接用短名：
  `llm` `memory` `store` `channel` `schedule` `persona` `tools` `permission` `audit` `identity` `notify` `skills` `gateway`。
- 若青梅被嵌入别的 Cordis 应用（例如作为 DSH 插件），由 `@qingmei/adapter-dsh` 用
  `ctx.isolate()` 做名字空间隔离，**不改业务包**。

**什么时候拆成三个包？** 只有一个判据：*这个角色的实现需要独立演进或替换*。

| 情况 | 怎么做 |
| --- | --- |
| 一种实现，短期不会换 | 一个包同时承担定义和实现（如 `persona`） |
| 需要换实现（库、模型、平台） | 拆 `service-x` + `provider-x-*` |
| 只是把能力暴露给模型 | 单独 `tool-*`，依赖服务即可 |
| 消费者也在演进（呈现方式常变） | 消费者独立成包，依赖定义包 |

**不要预防性拆分。** 一个 30 行的工具插件不需要先建三个包。

## 2. 服务总表

| 服务 | 定义包 | 职责一句话 | 典型提供方 |
| --- | --- | --- | --- |
| `store` | `service-store` | 结构化持久化 + 事务 + 迁移 | `provider-store-sqlite` / `-postgres` |
| `llm` | `service-llm` | 模型调用与嵌入，多提供方路由 | `provider-llm-deepseek` / `-ollama` / `-openai` |
| `memory` | `service-memory` | 记忆的写入、召回、遗忘 | `provider-memory-layered` |
| `persona` | `service-persona` | 人格包的加载、版本、场景切换 | 内置，可被 `persona-yaml` 覆盖 |
| `tools` | `service-tools` | 工具注册表与调用封装 | 内置 |
| `schedule` | `service-schedule` | 定时/周期/一次性触发 | 内置（store 支撑） |
| `channel` | `service-channel` | 渠道适配器注册与出站发送 | 内置（适配器为 `channel-*`） |
| `identity` | `service-identity` | 平台身份 ↔ 青梅 actor 的映射与绑定 | 内置 |
| `conversation` | `service-conversation` | 群/会话画像、标签与策略求值 | 内置 |
| `permission` | `service-permission` | 动作授权判定 | 内置（规则可插） |
| `audit` | `service-audit` | 只追加的审计流水 | 内置（store 支撑） |
| `notify` | `service-notify` | 跨渠道的主动触达路由 | 内置 |
| `skills` | `service-skills` | 技能包的发现与渐进加载 | 内置 |
| `harness` | `service-harness` | 拉起、驱动、回收外部 agent runtime | `harness-acp` / `harness-cli` |
| `self` | `core-self` | 自省、故障诊断、修复提案、请求换版（**核心层**） | 内置 |
| `autonomy` | `service-autonomy` | 自主循环、排期、行动白名单与投递 | 内置 |
| `gateway` | `service-gateway` | HTTP/SSE/WS 服务与路由注册 | `host-gateway` |

## 3. 契约

> 以下签名是**约定**，实现可加方法，不可改已有方法的语义。
> 所有方法都必须尊重传入的 `AbortSignal`，取消应尽快归还。

### store

```ts
type Row = { id: string }

export abstract class StoreService extends Service {
  abstract collection<T extends Row>(name: string): Collection<T>
  abstract transaction<T>(fn: (tx: Tx) => Promise<T>): Promise<T>
  abstract migrate(migrations: Migration[]): Promise<void>
}

interface Collection<T> {
  get(id: string): Promise<T | null>
  find(query: Query<T>): Promise<T[]>
  insert(value: Omit<T, 'id'> & { id?: string }): Promise<T>
  update(id: string, patch: Partial<T>): Promise<void>
  delete(id: string): Promise<boolean>
  count(query: Query<T>): Promise<number>
}

interface Query<T> {
  where?: Partial<T>
  order?: { field: keyof T; dir: 'asc' | 'desc' }[]
  limit?: number
  offset?: number
}
```

约束：`store` 不认识任何业务表；业务包自己声明 `Migration[]`，由 `qm-migrate` 插件统一调度。
SQLite 提供方开 WAL，写操作串行化；事务内禁止调用 `llm`（会长时间持锁）。

### llm

```ts
export abstract class LlmService extends Service {
  abstract providers(): LlmProviderInfo[]
  abstract chat(req: ChatRequest, signal: AbortSignal): AsyncIterable<ChatChunk>
  abstract complete(req: ChatRequest, signal: AbortSignal): Promise<ChatResult>
  abstract embed(texts: string[], signal: AbortSignal): Promise<number[][]>
  abstract register(provider: LlmProvider): Disposable
}

interface ChatRequest {
  messages: LlmMessage[]
  model?: string
  tools?: ToolSpec[]
  temperature?: number
  maxTokens?: number
  /** 敏感度：决定路由到哪个 provider，见 04 文档 */
  sensitivity?: 'public' | 'private' | 'secret'
  /** 任务类型，路由用：chat | tool-call | summarize | extract | embed */
  purpose?: string
  signal?: AbortSignal
}

type ChatChunk =
  | { type: 'text'; text: string }
  | { type: 'tool-call'; id: string; name: string; args: unknown }
  | { type: 'usage'; input: number; output: number }
  | { type: 'done'; stopReason: 'end' | 'tool-calls' | 'length' | 'error' }
```

`register()` 返回 disposer，提供方插件卸载时自动摘除。
路由（`qm-llm-router`）是消费方而不是 `llm` 的一部分：它订阅 `llm` 并实现 `purpose/sensitivity → provider` 的映射。

### memory

```ts
export abstract class MemoryService extends Service {
  /** 唯一写入入口：多端、多渠道、harness 上报都走这里 */
  abstract ingest(records: MemoryRecord[], opts?: IngestOptions): Promise<IngestResult>
  abstract recall(query: RecallQuery): Promise<RecallResult>
  abstract forget(selector: FactSelector): Promise<number>
  abstract summarize(sessionId: string): Promise<string>
  abstract profile(actorId: string): Promise<ProfileSnapshot>
}

interface MemoryRecord {
  kind: 'fact' | 'episode' | 'decision' | 'lesson' | 'artifact'
  subject?: string; predicate?: string; object?: string   // fact 用
  text?: string                                           // 其余类型用
  occurredAt?: Date
  origin: { kind: 'channel' | 'harness' | 'self' | 'doc' | 'schedule'; id: string; deviceId?: string }
  audience: 'owner' | 'family' | string                   // 'group:<id>' | 'device:<id>'
  confidence: number
  sensitivity: 'public' | 'private' | 'secret'
  /** 幂等键；缺省由服务端按 origin.id + 内容哈希生成 */
  idempotencyKey?: string
  links?: { toKey: string; kind: 'associative' | 'temporal' | 'causal'; weight: number }[]
}

interface IngestResult {
  created: string[]
  merged: string[]        // 命中已存在的事实，只追加 provenance
  rejected: { index: number; reason: string }[]
}

interface RecallQuery {
  text: string
  actorId: string
  scope?: MemoryScope[]
  channel?: 'dm' | 'group'
  /** 当前视口：决定 audience 过滤与呈现预算 */
  viewport?: { channel: ChannelId; deviceId?: string }
  limit?: number
  /** 注入 prompt 的 token 预算，超预算按优先级截断 */
  budget?: number
  includeSensitive?: boolean
}

interface RecallResult {
  facts: Fact[]            // 已按相关度 × 置信度 × 时效排序
  episodes: Episode[]
  tokensUsed: number
  /** 可解释：每个命中为什么出现 */
  why?: { neuronId: string; seed: boolean; hops: number; score: number }[]
}
```

行为约定：`recall` 必须**幂等且无副作用**（可缓存，不可写库）。
`ingest` 负责去重与冲突处理（同 `subject+predicate` 的新值使旧值 `validTo = now`），
且**幂等**：同一 `idempotencyKey` 重复上报只应用一次。
**`memory` 属于核心层**：不可热卸载，缺失时进程拒绝启动；图结构、激活与巩固见
[09 · 神经元记忆核心](09-神经元记忆核心.md)，跨端整合与视口过滤见
[10 · 跨端统一记忆](10-跨端统一记忆.md)。

### persona

```ts
export abstract class PersonaService extends Service {
  abstract get(scene: PersonaScene): Persona
  abstract list(): Persona[]
  abstract use(name: string, scene?: PersonaScene): void
}

interface Persona {
  id: string
  version: number
  displayName: string
  system: string
  /** 输出风格约束，拼在 system 之后 */
  style?: string[]
  /** 硬边界：不可被用户消息或工具结果覆盖 */
```

### tools

```ts
export abstract class ToolsService extends Service {
  abstract register(tool: ToolDefinition): Disposable
  abstract list(filter?: { tag?: string; scope?: 'private' | 'group' }): ToolDefinition[]
  abstract invoke(name: string, args: unknown, ctx: InvokeContext): Promise<ToolResult>
}

interface ToolDefinition {
  name: string
  description: string
  parameters: StandardSchemaV1            // 参数 schema，同时用于模型侧 JSON Schema
  scopes?: ('private' | 'group')[]
  sideEffect?: 'none' | 'write' | 'irreversible'
  timeoutMs?: number
  execute(args: unknown, ctx: InvokeContext): Promise<ToolResult>
}

interface InvokeContext {
  actorId: string
  sessionId: string
  channel: ChannelId
  signal: AbortSignal
  /** 需要用户确认的副作用操作，由 permission 服务弹出确认 */
  requestApproval?(reason: string): Promise<boolean>
}
```

`sideEffect: 'irreversible'` 的工具在群聊中**默认不可用**，私聊中也必须经过 `requestApproval`。

### harness

```ts
export abstract class HarnessService extends Service {
  abstract attach(id: string, opts: AttachOptions): Promise<HarnessHandle>
  abstract list(): HarnessStatus[]
  /** 注入给每个子会话的 MCP 声明（青梅自己） */
  abstract selfMcp(): McpServerDeclaration
  abstract runs(filter?: { taskId?: string; status?: TaskRunStatus }): Promise<TaskRun[]>
}

interface HarnessHandle {
  id: string
  capabilities: HarnessCapabilities
  newSession(opts: { cwd: string; model?: string; mcpServers: McpServerDeclaration[] }): Promise<HarnessSession>
  dispose(): Promise<void>
}

interface TaskRun {
  id: string
  taskId: string
  harnessId: string
  sessionId: string | null
  cwd: string
  status: 'queued' | 'running' | 'needs_approval' | 'done' | 'failed' | 'cancelled'
  progress: { phase?: string; percent?: number; note?: string; at: Date } | null
  budget: { tokens?: number; ms?: number }
  artifacts: ArtifactRef[]
}
```

约束：

- `attach()` 必须在 `ctx.effect` 内调用，句柄随插件卸载而释放；子进程不得成为孤儿。
- 明确不承诺的能力：操纵 harness 的 GUI、读取其未声明的工作区。
- `cwd` 只能来自青梅分配的 run 目录或用户显式授权的路径。
- 完整协议（ACP 方法、MCP 工具清单、审批桥、注入防护）见
  [07 · Harness 协作协议](07-Harness协作协议.md)。

### schedule

```ts
export abstract class ScheduleService extends Service {
  abstract create(spec: ScheduleSpec): Promise<Scheduled>
  abstract cancel(id: string): Promise<boolean>
  abstract list(ownerId?: string): Promise<Scheduled[]>
  abstract pause(id: string): Promise<void>
  abstract resume(id: string): Promise<void>
}

type ScheduleSpec =
  | { kind: 'at'; at: Date }
  | { kind: 'every'; everyMs: number; from?: Date }
  | { kind: 'cron'; expression: string; timezone: string }

interface Scheduled {
  id: string
  ownerId: string
  spec: ScheduleSpec
  payload: SchedulePayload     // { type: 'reminder' | 'tool' | 'prompt'; ... }
```

到点后 `ctx.emit('qm/schedule/due', scheduled)`，由 `qm-proactive` 决定怎么呈现。

### channel

```ts
export abstract class ChannelService extends Service {
  abstract register(adapter: ChannelAdapter): Disposable

interface ChannelAdapter {
  id: ChannelId                                  // 'qq' | 'feishu' | 'web'
```

### conversation

```ts
export abstract class ConversationService extends Service {
  /** 机器人被拉进新群时调用，创建 pending 画像 */
  abstract discovered(info: DiscoveredConversation): Promise<ConversationProfile>
  abstract get(id: string): Promise<ConversationProfile | null>
  abstract list(filter?: { channel?: ChannelId; status?: ProfileStatus }): Promise<ConversationProfile[]>
  abstract tag(id: string, tags: string[]): Promise<void>
  /** 策略求值：标签 → 信封；未知群返回最保守信封 */
  abstract resolve(id: string): Promise<PolicyEnvelope>
}

interface PolicyEnvelope {
  allowedClaims: string[]
  forbiddenTopics: string[]
  maxChars: number
  tone: 'formal' | 'neutral' | 'casual'
  refusalStyle: 'brief' | 'redirect-dm' | 'ask-owner'
}
```

约束：

- 未配置的群**必须**返回最保守信封（零记忆、零工具、一句话回复），不得回退到默认人格。
- `resolve()` 的结果要在**上下文组装之前**生效：把数据裁掉，而不是只告诉模型"别说"。
- 标签冲突取更严格者（`blocked > client > work > family > casual`）。
- 完整矩阵、发现流程与后台交互见 [11 · 群画像与回复策略](11-群画像与回复策略.md)。

### self

```ts
export abstract class SelfService extends Service {
  abstract report(incident: Incident): Promise<IncidentRecord>
  /** 命中 playbook 时跳过诊断，直接返回已知修复 */
  abstract diagnose(incidentId: string): Promise<Proposal>
  abstract propose(incidentId: string): Promise<Proposal>
  abstract apply(proposalId: string, approval: Approval): Promise<ApplyResult>
  abstract rollback(reason: string): Promise<void>
  abstract status(): Promise<{ version: string; releases: ReleaseInfo[]; incidents: IncidentRecord[] }>
}

interface Incident {
  /** 堆栈归一化后的哈希，用于去重与 playbook 索引 */
  fingerprint: string
  severity: 'low' | 'medium' | 'high'
  error: { name: string; message: string; stack?: string }
  traceId?: string
  context?: Record<string, unknown>
}
```

约束（违者视为安全缺陷）：

- `self` 与 supervisor 都在 **L3 禁止自改清单**内：任何补丁涉及它们一律拒绝，不是"需要审批"。
- `apply()` 只向 supervisor 发换版请求，自己不做文件替换。
- 没有人工 `Approval` 时，L2 补丁不得进入验证阶段；L0/L1 的自动改动必须留快照。
- 每一步（提案、审批、应用、回滚）都写 `qm_audit`。
- 完整分级、预算、熔断与验证准入见 [08 · 自进化与自修复](08-自进化与自修复.md)。

### autonomy

```ts
export abstract class AutonomyService extends Service {
  abstract tick(reason: 'timer' | 'event'): Promise<TickReport>
  /** 行动白名单；模型只能从中选，不能new */
  abstract actions(): ActionSpec[]
  abstract propose(req: ActionRequest): Promise<ProposalRef>
  abstract execute(specId: string, args: unknown): Promise<ActionResult>
  abstract traces(q: { since?: Date; level?: AutonomyLevel }): Promise<DecisionTrace[]>
}

interface ActionSpec {
  id: string
  risk: 'low' | 'medium' | 'high'
  reversible: boolean
  minLevel: AutonomyLevel            // A1 | A2 | A3
  budget: { tokens?: number; ms?: number }
  schema: StandardSchemaV1
}

interface DecisionTrace {
  at: Date
  level: AutonomyLevel
  worldState: Record<string, unknown>      // 快照摘要，不含敏感原文
  candidates: { action: string; score: number; dropped?: string }[]
  chosen: string | null
  reason: string
}
```

约束：

- 动作集合是**白名单**：未注册的动作一律不可执行，模型无法凭空发明。
- `reversible: false` 的动作无论级别多高都需人工确认；`minLevel` 不够直接拒绝。
- 每次 `tick` 必须产出 `DecisionTrace`；没有 trace 的主动行为按缺陷处理。
- 静默时段、每日打扰预算、冷却期在 `execute` 前硬校验，不依赖模型遵守。
- 完整分级、打扰经济学与环境维护边界见 [13 · 主动性架构](13-主动性架构.md)。

### notify

```ts

interface Notification {
  actorId: string
  blocks: Block[]
```

| `qm/turn/request` | `TurnRequest` | `qm-router` | `qm-agent` |
| `qm/turn/chunk` | `{ sessionId, chunk }` | `qm-agent` | `gateway` |
| `qm/turn/end` | `TurnResult` | `qm-agent` | 记忆抽取、审计、指标 |
| `qm/task/run-started` | `TaskRun` | `harness` | 任务面板、渠道通知 |
| `qm/task/progress` | `{ runId, progress }` | `harness-mcp` | 任务面板、审计 |
| `qm/task/finished` | `TaskRun` | `harness` | 通知、把结论写进账本与记忆 |
| `qm/schedule/due` | `Scheduled` | `schedule` | `qm-proactive` |
| `qm/channel/online` / `offline` | `{ channel, reason }` | `channel` | `notify`、健康面板 |
| `qm/memory/committed` | `Fact` | `memory` | 索引、同步 |
| `qm/permission/denied` | `PermissionRequest` | `permission` | 审计、告警 |
| `qm/tool/invoked` | `{ name, actorId, ok, ms }` | `tools` | 指标、审计 |

事件名一律 `qm/` 前缀 + 名词短语，**过去式表示已发生的事实**。

## 5. 配置与密钥

- 每个插件导出 `Config`（zod），加载即校验，失败信息必须指明字段路径。
- 密钥只来自环境变量或系统凭据库：`{ $env: 'NAME' }` 或 `{ $credential: 'feishu-app-secret' }`。
- 密钥**不得**进入：日志、审计 detail、插件状态快照、错误堆栈。
- 运行时读取密钥统一走 `secrets` 辅助（后续可作为 `service-secrets` 落地）；provider 内禁止直接 `process.env`。

## 6. 兼容与能力探测

- `service-*` 包带 `export const serviceVersion = 1`；破坏性变更才 +1。
- 提供方在 `package.json` 的 `qingmei.service` 字段声明 `implements`。
- 消费方不假设能力存在：`ctx.llm.providers()` 可能为空数组；空数组时应降级为固定话术而不是抛错。
- 已知的「可选能力」用 `ctx.inject()` 承载，不做运行时 `if`。
