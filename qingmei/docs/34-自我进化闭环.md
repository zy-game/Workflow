# 34 · 自我进化闭环

一句话：**经历 → 沉淀 → 提案 → 人审 → 应用 → 可回滚**。青梅现在只做前半段，后半段一律要人点头。

## 1. 两个写入口

| 入口 | 触发 | 产出 | 审核 |
| --- | --- | --- | --- |
| 教训 / 决策 | 回合或手动会话里的明确句式（「以后不要…」「这次踩坑…」「决定用…」） | 记忆候选（`kind=lesson/decision`） | 与事实共用一个待确认队列；采纳才写入记忆 |
| 技能草稿 | 任务以 `done` 收尾且结果 ≥ 20 字 | `qm_skill_draft`（`task-<id>`，含步骤/结果/产物） | 人在「技能」页 install；技能自带版本备份与 rollback |

抽取都走规则（[learn.ts](../packages/qm-distill/src/learn.ts)），不调模型；问句与假设直接跳过。

## 2. 接口

```bash
# 教训/决策候选（与事实同队列）
GET  /api/v1/memory/candidates
POST /api/v1/memory/candidates/decide   {id, allow}

# 技能草稿
GET  /api/v1/skills/drafts?status=proposed
POST /api/v1/skills/drafts/install      {id}   → skills.install()
POST /api/v1/skills/drafts/reject       {id}

# 技能回滚（qm-skill 已有）
GET  /api/v1/skills/history?name=<skill>
POST /api/v1/skills/rollback            {name, id?}
```

## 3. 边界（写死，不靠自觉）

- 进化只能改**提示词、技能、记忆**三类；
- 不改代码、不改权限、不改装配；
- 每次应用留版本快照：技能在 `skills/.backup/`，人格在 `personas/history/`；效果不好一条接口回滚；
- 草稿上限 20 条，满了不再生成，避免噪音堆积。

## 4. 验收

- 单测：教训/决策句式抽取、候选采纳写入 `kind=lesson`、成功任务生成草稿、拒绝后不可安装、重复收尾不重复生成；
- 生产：跑一个真实任务收尾后 `GET /api/v1/skills/drafts` 能看到草稿；
- 长期指标（尚未建立）：「同一类错误第二次是否少犯」——需要按失败原因聚类，看 7 天内重复率是否下降。

## 5. 复盘提案：应用后要能验证、能撤销（2026-11-12）

- **应用**：`POST /api/v1/review/proposals/apply` 记录 `applied_at` 与 `persona_history_id`（人格快照 id）；
- **效果**：下一期复盘生成时，对比「提案所属月份」与「本期」的失败回合率，
  写进 `effect_json`：`verdict=improved|flat|worse|unknown`，`delta` 为失败率变化；
- **撤销**：`POST /api/v1/review/proposals/rollback {id}` 调 `persona.rollback(history_id)`，提案置 `rolled_back`；
- 生产验证：`/review/proposals` 200，rollback 缺 id 返回 400。

## 6. 验收指标：同类错误第二次少犯

```bash
node scripts/error-recurrence.mjs          # 生产：cd /opt/qingmei && /opt/node24/bin/node scripts/error-recurrence.mjs
```

按 `error_code` 分组，统计「7 天内重复出现」的原因占比（`repeatRate`）。
当前生产 `failedTurns=0`（还没有带 error_code 的失败回合），所以基线为空；
等有失败数据后，这个数字就是进化是否有效的硬指标——**它不涨，说明教训没被用上**。
