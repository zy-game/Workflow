# 14 · 主动开场

> 「9 点问我早餐吃了么」——这句话机械上就是定时任务。
> 但一个定时任务和一个会搭话的助理，差别不在几点响，而在**它知不知道今天该不该问、问完记不记得、明天还会不会换个问法**。

## 1. 先回答那个问题

**自动化 + 自进化能做到吗？** 能，但要拆成三层看：

| 层 | 内容 | 谁来做 |
| --- | --- | --- |
| **触发** | 什么时候有机会开口 | 自动化（窗口 + 事件） |
| **判断** | 这次该不该开口、开口说什么类型 | 策略（代码）+ 判断（模型） |
| **内容** | 具体那句话、推荐哪三样 | 模型（内嵌 DSH）+ 记忆 + 工具 |

所以"自动化 + 自进化"够用了——**前提是别把三层混成一层**。
把三句问候写成 cron，就是三个推送；把它写成"窗口 + 判断 + 生成 + 学习"，才是搭话。

## 2. 提醒 vs 开场

| | 提醒 Reminder | 开场 Opening |
| --- | --- | --- |
| 目的 | 传递一个已知事实（9 点开会） | 开启一段可能有用也可能没用的对话 |
| 确定性 | 必须 100% 触发 | 可以决定"这次不说" |
| 内容 | 固定文案 + 时间 | 依赖今天的状态、昨天的对话 |
| 成功标准 | 你记得了 | 你回了，且下次还想回 |
| 失败形态 | 漏报 | 尬聊、假关心、问太多 |

**提醒必须走代码**（漏一个会议是真实损失）；**开场必须能不说**（说错一次就掉信任）。

## 3. 机会窗口

开场不挂在"9 点整"，挂在"一个允许开口的时间段"里，具体时刻由判断层决定。

| 窗口 | 时段 | 典型开场 | 每日上限 |
| --- | --- | --- | --- |
| 早餐 | 07:30–09:00 | 吃了么 / 今天有早会，先垫一口 | 1 |
| 午餐 | 11:00–11:30 | 快到饭点，要不要看看推荐 | 1 |
| 午后 | 14:00–15:00 | 昨天说的那个事推进了吗 | 1 |
| 晚餐 / 通勤 | 17:30–18:30 | 今天回不回家吃 | 1 |
| 夜间收束 | 20:30–21:30 | 明天想吃什么 / 明天三件事 | 1 |
| 周末 | 周六上午 | 这周有什么想做的 | 1 |

窗口之外不主动开口，除非 `urgent`（见 [13](13-主动性架构.md) §10）。

## 4. 开场状态机

```text
候选（窗口到了 + 有理由）
   │
   ├─ 判断：今天有必要吗？
   │     有理由（昨天说过、状态变化、目标相关）→ 继续
   │     没有理由 → 丢弃（不记录为用户可见事件）
   ▼
已开口 asked
   │
   ├─ 回答 answered → 写入事实/计划 → 影响明天
   ├─ 明确拒绝 "别问了" → 永久关闭该话题（写画像）
   ├─ 忽略 ignored ×2 → 该话题停一周
   └─ 延后 "晚点说" → 1 小时后重试一次，仅一次
```

**每条开场必须带一个理由**：来自记忆（"你昨天说今天带饭"）、状态（"你连续三天没吃早饭"）
或日程（"10 点有会，先吃点"）。没有理由的开场，就是骚扰。

## 5. 走查：一天里的四次开口

**07:50 · 早餐**

```text
窗口到了，判断：
  · 你有"记录饮食"的目标（或曾主动开启）
  · 昨天没记早餐
  · 今天 10 点有会（说明不宜空腹）
理由：昨天你说要开始记饮食 + 今天上午有会
开口：「早餐吃了么？」
快捷回复：[吃了] [还没] [今天别问]
```

**11:05 · 午餐**

```text
判断：
  · 你在公司（日程/定位）
  · 昨天说过"明天可能不带饭"
  · 附近有 3 家常点过的店（有历史记录）
理由：快到饭点 + 你昨天说可能不带饭
开口：「快到饭点了，这有三家你常点的，要不要看看？」
     附带 3 个选项，每个带一句为什么（近 / 上次你说好吃 / 人均 25）
```

**12:10 · 分支：带饭了**

```text
你回：「今天自己带了」
  → 写事实：meal:lunch = 自带（今天）
  → 建条件任务：明天 20:00，若"明天未定餐"，则开口
开口（次日 20:00）：「你明天想吃什么？我可以按你冰箱里的东西推荐两份」
```

**20:40 · 明日推荐**

```text
判断：
  · 明天无餐食计划
  · 冰箱清单有：鸡蛋、番茄、青菜（你上周报过）
  · 你周三通常加班（历史画像）
理由：明天没定 + 家里有菜 + 明天可能晚归
开口：「明天想吃什么？按你冰箱里的，我能出两份 20 分钟搞定的」
→ 你选一份 → 生成采购清单（缺什么）→ 问要不要加进明天的待办
```

这一整套里，**只有"07:30 到了"是自动化**。剩下的判断、分支、推荐、记住，都不是。

## 6. 为什么"纯自动化"不够

三个具体差别：

1. **连续性**：自动化不知道"你昨天说今天带饭"。要做到，必须有承诺/计划类记忆，并在第二天读到它。
2. **自适应频率**：自动化只会按设定响。助理要能从"你连续两天没回"里学到"该停一周"，
   从"你每次都回"里学到"可以多问一点"。这是自进化，不是配置。
3. **内容落地**：推荐餐点要有数据（菜单、冰箱、预算、健康目标、天气），要有取舍（你周三加班就别推费时的菜）。
   这是工具 + 记忆 + 生成，不是模板。

**判断标准**：如果一个开场去掉"昨天的对话"和"今天的状态"仍然成立，那它就是自动化通知，不该装成搭话。

## 7. 反模式

| 反模式 | 为什么坏 |
| --- | --- |
| 每天固定三问，风雨无阻 | 三天就会被静音，之后所有主动性一起失效 |
| 假关心（"今天也要加油哦"） | 没有信息量，也没有可执行动作 |
| 问了不用（推荐了菜却不记偏好） | 下次推荐还是老样子，用户会认为它没在听 |
| 只有问题没有选项 | 每条都要打字回复，成本太高，回应率会崩 |
| 把"没回"当成"没看到"继续追问 | 一次追问可以，两次就是骚扰 |

## 8. 学习什么

自进化在这里调的不是代码，是**三个旋钮**：

| 旋钮 | 初始 | 怎么学 |
| --- | --- | --- |
| 频率 | 每话题 3 次/周 | 忽略 2 次 → 1 次/周；连续 2 周回答 → 恢复 |
| 时机 | 窗口内固定时刻 | 记录你实际回复的时间，向那个时刻漂移（±15 分钟内） |
| 措辞 | 中性 | 你对简短/详细、正式/随意的反应，调整语气（C 类，可热更） |

所有调整都要有快照、可回滚，并出现在周期复盘的报告里。

## 9. 指标

| 指标 | 目标 |
| --- | --- |
| 开场回应率 | ≥ 50%（低于 30% 说明频率或内容有问题） |
| 明确反感（"别问了"） | ≤ 1 次/月 |
| 推荐采纳率 | ≥ 25% |
| 无理由开场 | 0 |
| 同话题重复措辞 | 0（7 天内不重复同一句） |
| 从"带饭"到"次日推荐"的衔接成功率 | ≥ 90% |

## 10. 里程碑

| 阶段 | 内容 | 工期 | 验收 |
| --- | --- | --- | --- |
| **A6** | 机会窗口 + 开场状态机 + 理由校验 | 2 周 | 每条开场都能回答"为什么现在说"；无理由不发送 |
| **A7** | 分支与承诺记忆（带饭 → 次日想吃什么） | 1 周 | 说"带饭"后，次日 20:00 正确触发推荐 |
| **A8** | 频率/时机学习 + 措辞变体 | 1 周 | 忽略两次自动降频；7 天不重复同一句 |

A6–A8 依赖 A1–A3 与 N+（跨端记忆）；约 4 周，建议在 A3 之后立刻做——
它是"贾维斯感"最直接的来源。
