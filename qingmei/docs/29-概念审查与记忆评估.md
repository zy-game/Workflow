# 概念审查与记忆评估

## 1. Web 记忆页

`apps/web/src/views/MemoriesView.vue`

四个视图：

```text
事实      现有事实的修正/删除（改动与删除写审计）
概念提案  合并/拆分提案，评估后应用，可回滚
待确认    会话凝练出的候选事实：采纳才进记忆；忽略可恢复；已采纳可按批撤回
画像      按 subject 聚合的高置信事实（memory.profile，owner 视角）
```

「待确认」与「画像」背后的行为：

- 候选由 `qm-distill` 在 `qm/turn/end` 产生，采纳才 `memory.ingest`（origin=distilled）；
- 误点忽略可 `POST /api/v1/memory/candidates/reopen` 恢复成待确认；
- 事实的修正/删除会写 `qm_audit`（`memory.fact.update|delete`），属于纠错留痕；
- 画像接口 `GET /api/v1/memory/profile` 只返回 owner 视角，群聊不注入。

概念提案：

```text
评估 → 查看影响概念/事件/重叠/风险
应用 → 只允许 canApply 的 merge/split
回滚 → 单条或批量回滚已应用变更
```

split 需要至少两个 session 分组；应用时会创建新概念并保留快照。
批量回滚会按变更逐条恢复，失败时保留未恢复的变更。

接口：

```text
GET  /api/v1/memory/stats
POST /api/v1/memory/consolidate
GET  /api/v1/memory/concepts/proposals
GET  /api/v1/memory/concepts/changes
POST /api/v1/memory/concepts/evaluate
POST /api/v1/memory/concepts/apply
POST /api/v1/memory/concepts/rollback
POST /api/v1/memory/concepts/rollback-batch
```

## 2. 记忆质量评估

回归集：`scripts/fixtures/memory-eval.json`（**59 条中文查询 / 59 条事实**，含近义干扰项）。
评估脚本：`scripts/eval-memory.mjs`，在临时 SQLite 里灌事实后按顺序跑查询，按召回条数 8（与生产默认一致）统计。

当前基线（2026-11-12，对召回打分做过一次改进，结果可复现）：

```text
queries   59
recall@1  78.0%
recall@3  89.8%
recall@8  94.9%
阈值      recall@3 ≥ 85%（低于则 gate 失败）
```

### 2.1 这次改了什么打分

原来只按「绑定激活 × 权重」求和，结果是同簇事实被高频词拉平。现在加了四项：

| 项 | 作用 |
| --- | --- |
| IDF | 被越多事实共享的神经元区分度越低（「咖啡」不该和「手冲」等权） |
| 字段权重 | 命中 object(×1.6) > subject(×1.3) > predicate(×1.1) |
| 命中词数 | 覆盖 2 个查询词的压过只覆盖 1 个的 |
| 子串奖励 | 查询与事实文本互为子串时加分（`手冲咖啡` / `咖啡豆` 这类） |

改进前后：recall@1 76.3% → 78.0%，recall@3 88.1% → 89.8%，recall@8 94.9%。

### 2.2 是否上语义召回（embedding）：**暂不上**

只剩 3 条查不到（5%），而且都是「查询与目标零词面重叠」的语义问题：

| 查询 | 期望 | 为什么词面召回救不了 |
| --- | --- | --- |
| 我平时喝什么咖啡 | 手冲咖啡 | 查询没有「手冲」，两者只共享「咖啡」 |
| 我多久跑一次步 | 每周三次 | 「跑步」与「每周三次」没有共同 token |
| 我喜欢看什么电影 | 科幻电影 | 查询只给类别词「电影」，需要把偏好与实体关联 |

不上的理由：

1. **收益只覆盖 3/59**：recall@8 已经 94.9%，embedding 最多把这 3 条捞回来；
2. **成本是长期的**：要引入模型（Ollama/bge-m3 或云嵌入）、向量存储与迁移、召回延迟；
3. **现有回退可用**：真召回不到时，`lexicalFallback` 与画像/摘要仍在上下文里，用户不会看到空白。

重新评估的触发条件（满足任一条再做）：

- 真实使用中「零词面重叠」的漏召回占抽样查询 > 15%；
- 回归集扩到 200 条以上且 recall@8 < 90%；
- 已经因为记忆问题出现可复现的「答非所问」并被用户纠正 ≥3 次。

到那时优先试 **sqlite-vec / Orama**（同库、无独立进程），不引入外部向量服务。

注意：这是**词面回归集**，只说明当前编码的能力边界，不代表真实用户分布；真实评估集仍未建立。

## 8. 分层退化与时间评估（2026-11-12）

```text
L0 原文        qm_message / qm_turn          热存 30 天
L1 单次经历    episode                       完整保留 7 天
L2 日/周摘要    episode(origin=summary)       7→日，28→周，90→月
L3 事实/概念    qm_mem_fact / qm_neuron       永久，随时间与纠错调整
```

规则（`memory.consolidateEpisodes`，服务器每天 04:00 由 cron 调 `scripts/memory-decay.mjs`）：

- 超过 7 天按天聚合、超过 28 天按周、超过 90 天按月；
- **不压缩**：`salience ≥ 0.8`、或文本含「决定/承诺/答应/教训/以后不/务必」；
- 摘要带 `provenance`（原始 episode id，最多 20 条），原文只置 `valid_to`（软删，可回溯）；
- 同一天/周/月重复跑不会产生重复摘要（按 `origin_id` 幂等）。

评估：`scripts/eval-memory-time.mjs` + 30 条时间锚定问题（事实分散在 1–700 天前）。

```text
cases 30 / recall@5 100%
```

注意：这组问题**刻意保留了对象关键词**，用来隔离「时间窗是否生效」；没有词面重叠的语义检索
仍是另一条路线（docs/29 §2.2 的触发条件），不要用这 100% 推断「语义召回已经不需要」。

## 9. 关系图（2026-11-12）

两张表，和记忆同一个 SQLite：

| 表 | 字段 | 说明 |
| --- | --- | --- |
| `qm_entity` | `name`（即 id）、`kind`、`aliases_json`、`valid_to` | 人 / 项目 / 地点 / 组织 / 主题 |
| `qm_edge` | `from_name`、`to_name`、`predicate`、`kind(fact\|cooccur)`、`weight`、`first_seen`、`last_seen`、`valid_from`、`valid_to` | 有向边，带时间与来源 |

构建方式：

- **事实入库时**：subject/object 各建实体，连一条 `fact` 边（权重=置信度）；
- **episode 入库时**：文本里出现已知实体的两两连 `cooccur` 边（0.2），只用来扩散关联；
- **实体过滤**：object 超过 16 字、带标点/括号、或以「不实/否认/情况/的事」开头的，不当作实体——
  关系图要的是「人/项目/地点」，不是整句话。

查询：

```bash
GET /api/v1/memory/graph?name=主人&depth=2
→ { entity, entities, edges, text }   # text 可直接拼进 prompt
```

召回时：取 top 3 事实的主客体，各查 1 跳邻居，把 `A —谓词→ B` 追加成【相关】块（最多 6 行）。

生产回填（2026-11-12）：`scripts/backfill-graph.mjs --reset` → **164 个实体 / 34 条边**。
边少的原因很直接：176 条事实里大部分 object 是长句或否定条目，被过滤掉了——这是有意的，
先把图做干净，再谈扩边。

限制：没有 NER，实体只能来自事实的主客体与已有实体名匹配；新话题不会自己变成节点。

## 10. 真实数据评估与可选的语义向量（2026-11-12）

评估集：`scripts/fixtures/memory-real-eval.json`（20 条生产事实原句 + 10 条换词重述 + 10 条语义同义但零字面重叠）。

```text
overlap（生产事实原句问法）：recall@5 95%（19/20）
near（换词、保留部分词）：    recall@5 90%（9/10，bigram 兜底后从 80% 提升）
zero（零字面重叠）：          recall@5 20%（2/10，仍是硬伤）
```

- **bigram**：中文按二字组再算一层相似度，`near` 组从 8/10 提到 9/10；
- **embedding（可选）**：新增 `provider-embedding-http`（OpenAI 兼容 `/embeddings`），
  装上后事实入库时存向量、召回时余弦相似度参与打分；**默认不装**，需要
  `QM_EMBEDDING_URL`（可选 `QM_EMBEDDING_KEY` / `QM_EMBEDDING_MODEL`）。
  单测用假向量验证「零字面重叠也能召回」的链路是通的，但没有真实向量服务时 zero 组仍是 20%。
- 结论：**没有向量服务，zero 组不可能靠词面工程解决**；评估已经把缺口量化，别再猜。
