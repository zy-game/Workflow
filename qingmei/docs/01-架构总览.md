# 01 · 架构总览

## 1. 目标与非目标

**目标**

- 一个长期陪跑的个人助理：记得住事、跟得住日程、管得了任务。
- 接入面可扩展：QQ、飞书、网页、桌面、手机，以及未来任何有 API 的东西。
- 能力可替换：模型、存储、检索、渠道、界面，任何一层都能单独换掉。
- 单机可跑，数据自持；要上云，是加插件而不是换架构。

**非目标（v1 明确不做）**

- 多租户 SaaS：青梅是一个人的助理，不是给一万人开账号的平台。
- 自研 DI / 自研事件总线：这些 Cordis 已经做对，重造只会更差。
- 自研大模型编排 DSL：一个薄 agent loop + 工具注册表足够，不上 LangChain 式抽象。
- 全平台离线可用：移动端是瘦客户端，见 [03](03-渠道与宿主.md#9-宿主)。

## 2. 设计原则

| # | 原则 | 具体表现 | 代价（明确接受） |
| --- | --- | --- | --- |
| P1 | **万物皆插件** | 内核只做加载、依赖、生命周期；没有一个「if 是 QQ 则……」的分支 | 插件边界画错时要返工；启动面比单体复杂 |
| P2 | **契约先于实现** | 每个能力先定 Service Definition 包，再有 Provider | 前期多写类型、多建包 |
| P3 | **一个助理，多个门** | 渠道/宿主不持有业务状态，业务状态只在服务里 | 渠道特有能力（按钮、卡片）需要降级层 |
| P4 | **本地优先** | 默认 SQLite 单文件、默认不出网 | 多设备同步要额外做（v1 只做单点 + 导出） |
| P5 | **副作用必须可撤销** | 所有注册走 `ctx.effect`，热重载不泄漏 | 写法更啰嗦，不能随手 `setInterval` |
| P6 | **主动但不打扰** | 日程/任务/目标驱动巡检，但有打扰预算和静默时段 | 需要调参，否则变成骚扰 |
| P7 | **可观测优先** | 每个 turn 一条 trace，每次工具调用可回放 | 日志与审计表会持续增长，需要归档策略 |

## 3. 分层与依赖方向

依赖只能自上而下，同层之间通过服务互相发现，**禁止反向依赖**。

```text
┌─ 宿主层 Hosts ────────────────────────────────────────────────┐
│ Web(Vue3) │ Electron │ Capacitor(APK) │ CLI │ 无头Daemon        │
└──────────────────────────┬─────────────────────────────────────┘
                           │ HTTP / SSE / WS（只认网关契约）
┌─ 传输层 Transport ────────▼─────────────────────────────────────┐
│ gateway（鉴权/会话/事件流）   channel-*（QQ/飞书/Web/邮件）        │
│   二者互不依赖，都只把消息翻译成 InboundMessage / OutboundEnvelope │
└──────────────────────────┬─────────────────────────────────────┘
┌─ Harness 层 Harness ────────────────────────────────────────────┐
│ harness（ACP client，拉起/驱动 DSH、ZCode…）                     │
│ mcp-server（接收子 agent 的进度、能力、审批请求）                 │
│   与渠道平级：渠道换消息，harness 换任务                          │
└──────────────────────────┬─────────────────────────────────────┘
┌─ 编排层 Orchestration ────▼─────────────────────────────────────┐
│ qm-router（去重/身份/权限/会话解析）  qm-agent（上下文+工具循环）   │
└──────────────────────────┬─────────────────────────────────────┘
┌─ 能力层 Services ─────────▼─────────────────────────────────────┐
│ llm · memory · persona · tools · schedule · store · identity ·  │
│ conversation · permission · audit · notify · skills · sync ·     │
│ harness · self · autonomy                                       │
└──────────────────────────┬─────────────────────────────────────┘
┌─ 核心层 Core ─────────────▼─────────────────────────────────────┐
│ 神经元记忆引擎（图 + 向量 + 激活 + 巩固）                        │
│ 自我模型（身份 / 价值 / 关系史 / 当前聚焦）                       │
│ self（自省 / 诊断 / 提案 / 请求换版）                             │
│   不可热卸载；缺失即拒绝启动                                       │
└──────────────────────────┬─────────────────────────────────────┘
┌─ 实现层 Providers ────────▼─────────────────────────────────────┐
│ store-sqlite · llm-deepseek · llm-ollama · memory-layered · …    │
└──────────────────────────┬─────────────────────────────────────┘
┌─ 内核 Kernel ─────────────▼─────────────────────────────────────┐
│ cordis：Context · Plugin · Fiber · Effect · Service · inject     │
└─────────────────────────────────────────────────────────────────┘
```

**关键约束**：`channel-*` 不得 import 任何 `provider-*`；`qm-agent` 不得 import 具体模型 SDK；
`harness-*` 只依赖 `harness` 服务定义，不得让业务代码感知 ACP 的方法名。
它们只依赖服务定义包里的类型。

**harness 层与渠道层的对称性**（详见 [07](07-Harness协作协议.md)）：
渠道把平台消息翻译成 `InboundMessage`；harness 把子 agent 的事件翻译成 `TaskRun` 的进度与产物。
两者都是青梅与外部世界的单向翻译边界，都不承载业务判断。

**青梅自己也跑一个 DSH 作为推理层**（ADR-013）。它同样通过 `harness` 服务接入，只是
cwd 与工具集受限；青梅在交给它之前完成画像、策略与记忆裁剪，拿到输出后做后置校验。
所以「治理」在青梅进程里，「表达与推理」在内嵌 harness 里（ADR-014）。

**主动性是编排层的一部分，不是附加功能**（详见 [13](13-主动性架构.md)）。
自主循环每 5 分钟取一次世界状态（目标/任务/日程/记忆热点/健康/在线/预算），
生成候选行动，经授权级别与打扰预算过滤后执行、排队或仅建议；每个动作都要留下
`decision trace`。没有 trace 的主动行为按缺陷处理。

## 4. Cordis 概念映射

| Cordis（`cordis@4`） | 青梅里的用法 |
| --- | --- |
| `Context` | 应用容器。服务就是挂在 ctx 上的属性，通过声明合并获得类型 |
| `ctx.plugin(P, config)` | 挂载一个插件，返回 `Fiber`。组合根唯一的挂载入口 |
| `Fiber` | 一个已加载插件实例的句柄；状态 `PENDING→LOADING→ACTIVE→UNLOADING→DISPOSED`，失败进 `FAILED` |
| `ctx.effect(fn)` | 所有外部资源的唯一获取方式，返回 disposer；热重载时自动撤销 |
| `ctx.inject(deps, cb)` | 「只在某服务存在时才生效」的子插件，用于可选能力 |
| `Service` 子类 | 服务提供方的标准写法：`class X extends Service { constructor(ctx){ super(ctx, 'memory') } }` |
| `Plugin.inject` | 必需依赖声明。服务不在就 `PENDING`，服务消失就自动卸载重来 |
| `Plugin.provide` | 插件向容器声明自己提供的服务名，供组合期校验 |
| `Plugin.Config` | StandardSchema（zod/schemastery 均可）校验配置，加载即失败 |
| `ctx.isolate()` / `intercept` | 同一进程跑多套配置（如两个 QQ 账号不同人格）时的隔离手段 |

青梅**只用 Cordis，不改 Cordis**。需要定制时写插件，不 fork 内核。

## 5. 插件分型与命名

| 类型 | 包前缀 | 例子 | 提供 service？ | 典型热重载场景 |
| --- | --- | --- | --- | --- |
| 服务定义 | `service-` | `@qingmei/service-memory` | 提供抽象类与类型 | 极少变，变了就是破坏性 |
| 提供方 | `provider-` | `provider-store-sqlite`、`provider-llm-deepseek` | 实现某 service | 换模型、换库 |
| 渠道 | `channel-` | `channel-onebot`、`channel-feishu`、`channel-watch` | 否（消费 `channel`） | 掉线重连、换账号 |
| Harness 适配 | `harness-` | `harness-acp`、`harness-cli` | 提供 `harness` | 换执行体、改启动参数 |
| 工具 | `tool-` | `tool-websearch`、`tool-calendar` | 否（消费 `tools`） | 经常增删 |
| 技能 | `skill-` | `skill-weekly-review` | 否 | 内容迭代 |
| 策略/编排 | `qm-` | `qm-agent`、`qm-router`、`qm-llm-router` | 视情况 | 调 prompt、调阈值 |
| 宿主桥 | `host-` | `host-gateway`、`host-static` | 提供 `gateway` | 改端口、改鉴权 |
| 核心 | `core-` | `core-memory`、`core-self` | 提供 `memory` / `self` | **不热重载**，发版才换 |

命名规则：**服务名 = 包名去掉 `service-` 前缀**（`service-memory` → `memory`）。一个包只提供一个服务。

## 6. 组合根

青梅的「main 函数」是一份 YAML，不是一段代码。所有装配关系对使用者可见、可改、可版本化。

```yaml
# qingmei.yml
- name: '@qingmei/provider-store-sqlite'
  config: { path: './data/qm.db' }

- name: '@qingmei/provider-llm-deepseek'
  config:
    baseURL: 'https://api.deepseek.com'
    model: 'deepseek-chat'
    apiKey: { $env: 'QM_DEEPSEEK_KEY' }     # 密钥永不写进 YAML

- name: '@qingmei/provider-llm-ollama'
  config: { baseURL: 'http://127.0.0.1:11434', model: 'qwen2.5:7b' }

- name: '@qingmei/qm-llm-router'
  config:
    routes:
      secret: ollama        # 敏感内容只走本地模型
      tool-call: deepseek
      default: deepseek

- name: '@qingmei/provider-memory-layered'
- name: '@qingmei/qm-agent'
- name: '@qingmei/qm-router'

- name: '@qingmei/channel-onebot'
  config: { endpoint: 'ws://127.0.0.1:3001', selfId: '${QM_QQ_ID}', accessToken: { $env: 'QM_ONEBOT_TOKEN' } }

- name: '@qingmei/channel-feishu'
  config: { appId: '${QM_FEISHU_APP_ID}', appSecret: { $env: 'QM_FEISHU_SECRET' } }

- name: '@qingmei/host-gateway'
  config: { port: 7410, cors: ['http://localhost:5173'] }
```

`{ $env: NAME }` 是青梅组合根约定：加载时从环境变量取密钥，缺失则启动失败并明确报错。
`${NAME}` 是普通变量插值，用于非敏感配置。

## 7. 最小可运行骨架

```ts
// apps/server/src/index.ts —— 不用 loader 时的等价写法
import { Context } from 'cordis'
import StoreSqlite from '@qingmei/provider-store-sqlite'
import MemoryLayered from '@qingmei/provider-memory-layered'
import LlmDeepseek from '@qingmei/provider-llm-deepseek'
import Agent from '@qingmei/qm-agent'

const ctx = new Context()
ctx.plugin(StoreSqlite, { path: './data/qm.db' })
ctx.plugin(MemoryLayered)
ctx.plugin(LlmDeepseek, { model: 'deepseek-chat' })
ctx.plugin(Agent)
```

一个服务定义（只含类型和抽象类，不含任何实现）：

```ts
// packages/service-memory/src/index.ts
import { Service, type Context } from 'cordis'

declare module 'cordis' {
  interface Context {
    memory: MemoryService
  }
}

export abstract class MemoryService extends Service {
  constructor(ctx: Context) {
    super(ctx, 'memory')
  }
  abstract remember(draft: FactDraft): Promise<Fact>
  abstract recall(query: RecallQuery): Promise<RecallResult>
  abstract forget(selector: FactSelector): Promise<number>
}
```

一个消费方（声明依赖，服务缺失时保持 `PENDING`，不会半启动）：

```ts
// packages/qm-agent/src/index.ts
import type { Context } from 'cordis'

export const name = 'qm-agent'
export const inject = ['llm', 'memory', 'persona', 'tools']

export function apply(ctx: Context) {
  ctx.on('qm/inbound', (msg) => runTurn(ctx, msg))
}
```

## 8. 一次对话的完整时序

```text
QQ / 飞书 / Web
      │  1. 平台事件
      ▼
channel-*  ──2. 归一化──▶  ctx.emit('qm/inbound', InboundMessage)
                                │
                                ▼
                          qm-router
                     3. 幂等去重（平台消息 id）
                     4. 身份解析（sender → actor）
                     5. 权限判定（permission）
                     6. 会话解析（channel+conversation+actor → session）
                                │  7. ctx.emit('qm/turn/request')
                                ▼
                          qm-agent
      ┌─────────────────────────┼──────────────────────────┐
      │ 8a. 组装上下文           │ 8b. 工具循环              │ 8c. 预算控制
      │  persona.system          │  tools.list()            │  maxSteps / 超时
      │  memory.recall()         │  llm.chat({tools})       │  token 预算
      │  schedule.today()        │  执行 tool → 回灌结果      │  失败降级话术
      └─────────────────────────┼──────────────────────────┘
                                │ 9. 流式分块
              ┌─────────────────┴──────────────────┐
              ▼                                    ▼
      gateway ──SSE──▶ Web/桌面/手机        channel.send() ──▶ QQ/飞书
                                │
                                ▼
                     10. 落库：message / turn / audit
                     11. ctx.emit('qm/turn/end') → 记忆抽取（异步，不阻塞回复）
```

要点：

- **回复与记忆解耦**：先回复，再抽取。抽取失败不影响对话，只进补偿队列。
- **幂等**：平台重投的同一条消息只会产生一个 turn（`channel + platformMessageId` 唯一）。
- **跨渠道同人**：身份绑定后，QQ 上说的话，飞书上能被召回（见 [identity](02-服务契约.md#identity)）。
- **流式**：QQ/飞书不支持流式就整段发送，Web 走 SSE。降级在渠道适配器内完成，agent 不感知。

## 9. 生命周期纪律

这四条是青梅代码评审的硬性检查项：

1. **一切外部资源进 effect。** 定时器、连接、watcher、文件句柄，一律
   `ctx.effect(() => { ...; return () => cleanup() })`。在 effect 外 `setInterval` 视为缺陷。
2. **`inject` 是持续依赖，不是启动检查。** 不要写 `if (ctx.database) {...}`；
   要用就声明 `inject`，只在部分功能上依赖就用 `ctx.inject([...], cb)` 开子插件。
3. **`apply` 里不做长任务。** 需要常驻循环的，用 effect 启动并在 disposer 里取消信号。
4. **有顺序的拆卸放进同一个 disposer。** 异步 disposer 是并发执行的，逆序只保证启动顺序。

**PENDING 是头号排障对象。** 插件「没反应」通常不是报错，而是依赖缺失导致永久 `PENDING`。
因此 `qm doctor` 必须能输出：全部 fiber 树、每个 fiber 的状态、缺失的依赖名、最近一次状态迁移原因。

## 10. 进程与拓扑

| 拓扑 | 形态 | 适用 | 代价 |
| --- | --- | --- | --- |
| A 单机全包 | Electron 托盘进程内嵌内核 + SQLite | 个人自用，最省事 | 关机即离线 |
| B 家庭常驻 | 小主机/NAS 跑 `qm serve`，渠道用**长连接出网**，不开入站端口 | 需要 7×24 在线 | 要一台常开的机器 |
| C 云边混合 | 云上只做渠道接入与转发，数据留本地 | 多设备、弱网 | 同步与一致性复杂度陡增（v1 不做） |

B 是推荐形态：飞书长连接、OneBot 反向 WS 都是**出站连接**，不需要公网 IP，也不需要备案。
