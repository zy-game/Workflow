# 13 · 主动性架构

> 贾维斯不是"回答得快"，是"知道什么时候该出现"。
> 被动助理的输入是消息，主动助理的输入是**世界状态**：时间、任务、记忆、健康、你在不在线。

## 1. 响应式与主动式的差别

| | 响应式（当前大多数产品） | 主动式（青梅的目标） |
| --- | --- | --- |
| 触发 | 用户发消息 | 时间、事件、目标缺口、系统状态 |
| 决策依据 | 这句话怎么答 | 现在该不该做、做什么、做多少 |
| 失败形态 | 答得不好 | **打扰过度**、自作主张、成本失控 |
| 核心能力 | 语言 | 排期、判断时机、收敛行动 |

主动式的第一原则：**无事可做时必须沉默。**
不允许为了证明存在感发消息——那不是贾维斯，那是推送机器人。

## 2. 三个前提

一个系统要"知道什么时候做什么"，得先具备三样东西：

1. **世界状态**：目标、任务、日程、记忆热点、系统健康、你的在线状态与作息画像。
2. **行动边界**：能做哪些动作、每个动作多大风险、可不可逆、要不要人批。
3. **沉默的判断力**：知道什么不值得说。这一条最难，也最决定体验。

## 3. 自主循环

```text
              ┌────────────── 每 5 分钟 tick ──────────────┐
              │  空闲时退避到 15 分钟；事件可直接唤醒        │
              ▼
 ① 世界状态快照   目标 · 任务 · 日程 · 记忆热点 · 系统健康 ·
                 在线状态 · 预算余额 · 今日打扰额度
              │
 ② 候选生成       规则候选（代码：到点提醒、逾期、磁盘告警）
              +  判断候选（内嵌 DSH：现在最值得做的一件事是什么）
              │
 ③ 过滤           授权级别 · 预算 · 静默时段 · 重复抑制 · 冷却期
              │
 ④ 排序           价值 = 紧急度 × 影响面 × 成功概率 ÷ 打扰成本
              │
 ⑤ 执行/排队/建议   A2/A3 直接做；A1 只建议；A0 只记录
              │
 ⑥ 记账           decision trace：看到了什么、考虑了哪些、为什么选它、为什么放弃别的
              │
 ⑦ 复盘           做成了吗？被打断了吗？用户忽略了吗？→ 调权重、降频、写画像
```

第 ② 步是**混合生成**：规则负责确定性与兜底，模型负责"什么值得做"。
第 ⑥ 步是可解释性的根：没有 decision trace 的主动行为，等同于骚扰。

## 4. 行动空间

行动必须是一个**有限白名单**，否则模型有了系统权限就等于有了破坏力。
每个动作带风险元数据，由执行器校验，而不是靠提示词。

| 动作 | 风险 | 可逆 | 最低级别 | 说明 |
| --- | --- | --- | --- | --- |
| `notify.self` | 低 | 是（只是消息） | A1 | 私聊自己/发一条提醒 |
| `task.enqueue` | 低 | 是 | A2 | 往排期器加任务 |
| `harness.dispatch` | 中 | 是（可取消） | A2 | 派任务给有工作区的 harness |
| `memory.consolidate` | 中 | 是（有快照） | A2 | 触发夜间记忆整理 |
| `env.cleanup` | 中 | 是（回收站 7 天） | A2 | 清理缓存/日志/临时目录 |
| `tag.propose` | 低 | 是 | A2 | 提议群标签 |
| `persona.tune` | 中 | 是（版本快照） | A3 | 调整 C 类人格/提示词 |
| `self.repair` | 高 | 是（自动回滚） | A3 | 自修复（见 08） |
| `focus.enforce` | 中 | 是（定时结束） | A3 | 专注模式 / 全屏遮罩，需任务合同授权 |
| `device.lock` | 高 | 是（30s 可取消） | A3 + 合同 | 仅 Android，需设备管理员权限 |
| `outbound.send` | 高 | **否** | 永远人工 | 对外发消息、转账、提交 |
| `delete.permanent` | 高 | **否** | 永远人工 | 永久删除数据 |

两级闸：**级别不够不许执行**，**不可逆动作永远人工确认**——两条独立生效。

## 5. 主动性分级

| 级别 | 行为 | 典型 |
| --- | --- | --- |
| **A0 观察** | 只记录，不动作 | 新装第一周 |
| **A1 建议** | 产生建议，等你点头 | 新群标签、"要不要我帮你盯这个" |
| **A2 代理** | 低/中风险自主执行，事后报告 | 到点提醒、派任务、清缓存、记忆整理 |
| **A3 托管** | 可撤销的中高风险自主执行 | 自修复、调人格、重排任务优先级 |

**信任是挣来的，不是配出来的**：

- 连续 10 次建议被采纳、0 次回滚 → 升一级。
- 1 次回滚或被投诉 → 降一级，并记入画像。
- 升级/降级都要通知你，并可在设置里锁死当前级别。

这条机制解决了一个真实矛盾：你希望它主动，但不敢一上来就放手。

## 6. 排期器

"对任务排期"不是把任务塞进队列，而是回答：**现在做哪个、什么时候做、做不完怎么办。**

- **优先级**：紧急度 × 影响面 ÷ 成本；截止日临近自动加权。
- **时间窗**：工作时间 / 家庭时间 / 静默时段。工作类任务不进家庭时间窗。
- **依赖**：DAG。前置未完成则阻塞，不空转。
- **抢占**：高优任务可打断低优，但要求低优先落 checkpoint（否则不允许抢占）。
- **容量**：同时最多 N 个 harness run；超出排队而非并发轰炸。
- **放弃**：超过期限且价值衰减的任务自动降级为"下周期再看"，而不是无限挂着。

## 7. 项目审问：从 QQ 一句话到三行汇报

这是主动性最典型的闭环——**按需拉取，而不是等它主动汇报**。

```text
你在 QQ： “青梅，项目 X 现在什么情况？”
   │
   ├─ 1. 意图识别：project.inquiry(X)，属于工作群（策略信封允许 task-progress）
   ├─ 2. 查账本：最近 TaskRun、进度、阻塞、上次快照时间
   ├─ 3. 判断新鲜度：
   │      快照 < 2 小时 → 直接用，回复里标注时间
   │      否则 → 派任务
   ├─ 4. 找工作区：哪个 harness 挂了项目 X 的 cwd？
   │      有 → harness.dispatch（只读盘点，不改代码）
   │      无 → 回复「没有可用的工作区，要我起一个吗？」
   ├─ 5. 等待汇报：qm_report_progress 流式回传，超时 90s 先回「正在进行」
   ├─ 6. 汇总：3 行结论 + 阻塞项 + 可选详情链接
   └─ 7. 回 QQ
```

设计要点：

- **审问是只读的**。默认派发的任务是"盘点状态"，不是"改代码"。要改，另起一次带审批的任务。
- **必须能降级**：harness 全不可用时，用账本最后一次快照回答，并明确标注"数据截止 X 点"。
- **超时先说一句**，不要让用户干等——"正在问 X 的工作区，30 秒后回你"。
- 同一个项目 10 分钟内被问两次，第二次直接用缓存。

## 8. 记忆整理与热点打分

你说得对：**这件事不该写成代码，应该交给模型判断。** 但要给它边界。

```text
夜间 03:00（或空闲触发）
  ├─ 取过去 24h 的情节与候选事实（≤200 条，脱敏后）
  ├─ 交给内嵌 DSH，用固定评分卡：
  │     提及频次 · 情绪强度 · 目标关联 · 跨端一致性 · 用户显式强调
  │     输出：每条 salience(0..1)、建议层（工作/长期/冷存）、合并建议
  ├─ 代码侧校验：单条调整幅度 ≤0.3、每次最多降层 20% 节点、
  │              任何"删除"只降层不真删（真删走用户指令）
  ├─ 应用 + 快照 + 审计
  └─ 生成一句话报告：「这周记住了 3 件重要的事，淡化了 11 条闲聊」
```

分工很清楚：

- **模型做判断**：哪条重要、哪两条其实是一件事、哪些该忘。
- **代码做约束**：幅度上限、批量上限、不真删、可回滚、可审计。

没有约束的自动打分，一个月后你会发现它把你的重要记忆全淡化了，而且无法解释。

## 9. 环境自维护

这是"强人工智能"里最不性感、但最能体现"它在替我操心"的部分。

| 任务 | 频率 | 动作 | 边界 |
| --- | --- | --- | --- |
| 日志轮转 | 每日 | 压缩 7 天前、删 30 天前 | 审计日志除外 |
| 临时目录清理 | 每日 | `tmp/`、构建缓存、下载残留 | 回收站保留 7 天 |
| 孤儿进程 | 每小时 | 回收无主的 harness/CLI 子进程 | 白名单进程不动 |
| 数据库维护 | 每周 | WAL checkpoint、VACUUM | 低峰期，限速 |
| 备份校验 | 每周 | 试恢复一份到临时目录 | 失败立刻告警 |
| 磁盘水位 | 持续 | <10% 告警，<5% 激进清理 | 不动用户文档 |
| 依赖与镜像 | 每月 | 清理未使用缓存 | 不自动升级 |

硬规则：

1. **只清 `data/cache`、`data/tmp`、日志、构建产物**；`data/qm.db`、凭据、release 目录、审计库永不触碰。
2. **先 dry-run**：头三次只报告"我准备删这些"，你确认后才真删。
3. **软删除**：进 `.trash/`，7 天后才物理清理。
4. **每次都要报告**：清理了多少、释放多少空间、有没有异常项。
5. **磁盘告急时先通知再动手**，除非已经低于 5%（此时保命优先）。

## 10. 打扰经济学

主动消息的成本不是 token，是**你的注意力**。

| 机制 | 规则 |
| --- | --- |
| 每日预算 | 非紧急主动消息默认 3 条/天 |
| 静默时段 | 默认 23:00–08:00，仅 `urgent` 可穿透且必须说明理由 |
| 合并 | 同一主题 30 分钟内合并成一条 |
| 降级 | 低价值不进即时消息，进当日/每周摘要 |
| 学习 | 同类消息被忽略 3 次 → 降频 50%；再忽略 → 只进摘要 |
| 冷却 | 同一动作 24 小时内不重复触发（除非状态变化） |

判断标准很朴素：**这条消息能不能让你做一个决定或采取一个动作？** 不能就不发。

**开场是主动性的最小单位**：一次有理由的搭话，而不是一条通知。窗口、状态机、理由校验与
「带饭 → 次日推荐」的分支，见 [14 · 主动开场](14-主动开场.md)。

## 11. 可解释性

每条主动行为都要能回答三个问题：

1. 你看到了什么？（输入快照）
2. 你考虑过什么、为什么选这个？（候选与排序）
3. 为什么是现在？（触发条件）

落在 `qm_audit` 的 `decision` 里，后台"主动性"页面可回看。
没有这个，你无法校准它，也无法在它做错时定位是"判断错"还是"边界错"。

## 12. 失败模式

| 失败 | 表现 | 对策 |
| --- | --- | --- |
| 过度主动 | 一天十条"在吗" | 预算 + 价值门槛 + 忽略学习 |
| 幻觉行动 | 声称做了没做的事 | 每个动作有执行回执；没回执不算完成 |
| 循环触发 | 清理→告警→清理 | 冷却期 + 单日次数上限 + 熔断 |
| 成本爆炸 | 每 5 分钟跑一次模型 | tick 退避、闲时降频、规则优先 |
| 自作主张 | 未经授权改了东西 | 分级 + 不可逆动作人工 + 回滚 |
| 沉默失效 | 该提醒时没提醒 | 关键日程走确定性规则，不依赖模型判断 |

最后一条很关键：**越重要的事越不能依赖模型临场发挥**。
"9 点开会"这类硬提醒走代码；"要不要提醒你带伞"这类软判断交给模型。

## 13. 指标

| 指标 | 目标 |
| --- | --- |
| 主动消息采纳率 | ≥ 60%（采纳=点开/回复/执行） |
| 打扰投诉率 | ≤ 1 次/月 |
| 无价值主动消息占比 | ≤ 10% |
| 决策可解释率 | 100%（无 trace 视为缺陷） |
| 环境维护成功率 | ≥ 99%，零误删 |
| 审问响应 | 有缓存 < 3s；需派任务 < 90s 给首条结论 |

## 14. 里程碑

| 阶段 | 内容 | 工期 | 验收 |
| --- | --- | --- | --- |
| **A1** | 自主循环骨架（tick、世界状态、decision trace）+ A1 建议模式 | 2 周 | 每天给出 ≤3 条建议，全部可在后台看到理由 |
| **A2** | 排期器 + 行动白名单 + A2 代理（提醒/派任务/清理） | 2 周 | 到点提醒零漏报；清理只动白名单目录 |
| **A3** | 项目审问闭环（QQ → harness → 汇总 → 回复） | 2 周 | 90s 内给出首条结论；无工作区时正确降级 |
| **A4** | 记忆热点打分 + 夜间整理 + 周报 | 2 周 | 打分可回滚；报告可读且与审计一致 |
| **A5** | 信任升级/降级 + 打扰经济学调优 | 1 周 | 连续 10 次采纳自动升级；忽略 3 次自动降频 |

A1–A3 依赖 H（harness 集成）与 M2（工具与日程）；A4 依赖 N（神经元记忆）。
预计 9 周，可与 G/N+ 并行。
